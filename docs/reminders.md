# 提醒功能设计

## 用户端规则

- 提醒事件仅包括报名开始和报名截止。
- 预设提前时间为1、3、5、7、15天及1、3个月，另支持早于目标事件的自定义日期时间。
- 已经过去的提醒时间不可选择；赛事时间未公布或目标事件已经过去时不可保存。
- 保存站内提醒后才请求微信订阅消息授权。拒绝授权或模板尚未配置时仍保留站内提醒。
- 用户可在“我的提醒”查看、编辑、删除和主动再次授权。
- 取消收藏但存在提醒时，必须让用户选择保留提醒或同时删除。

## 时间更新

提醒保存 `target_at` 和 `offset_ms`。赛事目标时间发生变化时，未触发提醒按新目标时间减去原偏移量重新计算，并标记 `time_updated`；延期标记 `postponed`。赛事取消即使目标时间未变化，也会把未触发提醒同步为 `schedule_change_status=cancelled`、`delivery_status=cancelled`，定时函数不会发送。已经发送或正在发送的提醒不回写。

## CloudBase执行边界

- 小程序不得直接写 `reminder` 集合；正式环境通过云函数把 `openid` 映射为 `user_id`。
- 定时云函数按 `remind_at` 从早到晚扫描 `delivery_status=pending/failed`、已授权、日程未取消且已到期的记录，采用条件更新抢占为 `queued`，防止并发重复发送。
- 发送成功写 `sent/sent_at`，失败写 `failed/last_error/retry_count`；认领超时同样计入重试，达到阈值写为 `manual_required` 并退出到期扫描，避免失败记录长期占满批次。
- 客户端合并提醒时不得覆盖云端 `sent` 或 `queued` 记录，防止旧的本地 `pending` 状态造成重复发送或释放正在处理的认领。
- 提醒登录合并按每批10条执行，以适配当前3秒函数上限；单个事件最多保存8条方案。替换事件提醒在一个数据库事务中完成，批内任一写入失败会整体回滚。
- 定时函数在代码层同时校验无微信用户 `OPENID`、`Type=Timer`、触发器名称和触发时间；这些字段属于纵深防御，客户端仍可能伪造普通事件参数，不能替代函数权限。在云函数“权限控制”中必须应用 `database/function-security-rules.json`，将 `sendReminders.invoke` 设为 `false`。该规则只阻止客户端调用，不影响定时触发器。仓库文件不会自动修改云环境权限，必须在控制台应用并复核。
- 微信订阅授权不是永久授权，必须按实际模板和当时平台规则处理，不能向用户承诺永久推送。
- `sendReminders` 按每5分钟触发，`REMINDER_BATCH_SIZE` 可配置为1–50，未配置时保守地每批只处理1条。若要提高到50条，云函数超时时间应先在控制台配置为至少30秒；部署后必须用函数信息页或 CLI 核对云端实际值，不能只以仓库声明为准。当前已核验的开发环境仍是3秒，因此不得直接把批次调大。
