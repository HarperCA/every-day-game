# 大学生专业赛事数据质量 SLA

版本：1.1 · 更新日期：2026-09-23 · 业务时区：Asia/Shanghai

本文定义后续筛选、入库、发布与清洗的验收准绳。目标值是应实现的验收标准，不代表当前已达到，也不代表 AI 可以保证零错误。未采集的指标必须显示“未测量”，不得显示为达标或零问题。

## 1. 业务范围和数据分区

合格数据是一场身份可确认、当届有官方依据、允许大学生参与、具有专业学习或专业技能任务的比赛。排除中小学专属赛事、兴趣娱乐、群众体育、培训和证书营销活动。

- 线索区：通知、目录、媒体报道、搜索结果及身份/资格/专业关联证据不足的候选。可以继续抓取追溯，但不属于比赛库，不计入新增量。
- 合格草稿：比赛身份、大学生资格、专业关联已核验，但尚缺发布所需资料。不得用草稿容纳尚未确认是比赛的文章。
- 已发布：合格草稿满足发布门槛，审核通过且公开数据与证据一致。
- 误收隔离：入库后确认或怀疑为非赛事、重复或严重失实的记录。保留原记录、证据和审计，不由 AI 自动永久删除。

通知可以作为正式证据，但记录名称必须是从中核验出的具体比赛；不得仅删除标题中的“通知”二字就视为核验完成。没有独立官网时，允许主办方或承办方正式赛事页面。

赛事标题 `name` 只保存比赛的主体名称，不包含年份或“第几届”。当届年份和届次分别保存在 `editionYear`、`editionOrdinal`，并在详情页单独展示；原始官方届次文字保存在 `editionName` 供溯源。不得从记录 ID 猜测年份或届次；官方依据不明时相应字段留空。跨赛事复合标题含多个届次时须保留全部届次并标记待人工澄清，不得合并为一个届次。新建和改名时执行此规则，存量数据按有备份的迁移清单处理；标准标题相同不等于重复赛事，仍须结合主办方、地域和届次判重。

## 2. 逐条硬门槛

以下任一项不满足，不得新增为合格赛事；不得以总分、权威单位关键词或 AI 自报置信度抵消。

| 检查项 | 合格草稿要求 | 发布附加要求 |
| --- | --- | --- |
| 赛事身份 | 具体赛事名称、当届名称/年份、主办方；正式来源及对应原文依据 | 与公开标题、届次一致，无待解决身份争议 |
| 大学生资格 | 官方原文明确大学生、本科生、研究生、高职等适用对象；保留资格条件 | 如实展示地域、学校、年级和专业限制 |
| 专业关联 | 官方任务/规则原文能证明专业技能关联，并有专业分类 | 分类与任务一致，不能仅因标题含“创新”通过 |
| 唯一性 | 按赛事身份、届次、主办方、地域范围交叉去重 | 无未解决的疑似重复 |
| 来源 | 官方页面可核验，记录原始网址、最终网址、证据摘录和核验时间 | 发布前 24 小时内重新核验关键来源；失效不得发布 |
| 时间 | 未知日期留空，区分“未核实”与“官方明确待公布” | 报名状态可由证据解释；“时间待公布”须有当届明确依据 |
| 费用与规则 | 只填写有出处的事实；未说明费用不能写“免费” | 展示内容不得误导；必要的报名、资格、赛制信息完整 |
| 报名入口 | 新闻链接不得充当报名入口；来源、官网、报名入口分别保存 | 按当前产品发布校验执行；学校统一报名等不得伪造自助入口 |
| 审核 | 不自动填“已审核”“已通过” | 实际完成审核，版本及审核主体可追溯 |

“新增至少 N 场”的计数额外排除：已截止赛事、原库已有记录、同一赛事赛道、校内选拔及国赛的重复分赛区。不同省份独立主办的赛事可分别计数；旧记录补资料不计新增。到期的历史赛事可保留归档，但不能继续标记报名中。

## 3. 质量维度与验收指标

统计窗口：每个导入批次 + 每日北京时间 00:00—24:00。批次使用写入前后快照及实际新增 ID 对账；报告保留分子、分母、排除原因和规则版本。样本数为 0 时记 N/A，不记 100%。

| 维度 | 指标定义 | 目标/门槛 | 不达标处理 |
| --- | --- | --- | --- |
| 有效性 | 身份、大学生资格、专业关联全部有可核验证据的新增记录数 / 实际新增数 | 100%；验收发现非赛事或范围错误 0 条 | 停止该批次验收，相关条目退回线索/隔离，扩大复查 |
| 完整性 | 通过第 2 节对应状态全部必需项的记录数 / 该状态受检记录数 | 合格草稿及发布记录均 100%；可选字段缺失率单独披露 | 缺身份材料退线索；仅缺发布材料留合格草稿 |
| 准确性 | 与官方原文一致的已核对字段数 / 已核对字段数 | 非关键字段抽查正确率 ≥98%；关键身份、资格、入口、报名截止错误 0 项 | 任一关键错误阻断验收；非关键不足扩查并修正 |
| 一致性 | 通过类型、枚举、日期顺序、关联主键和状态逻辑检查的记录数 / 受检数 | 100% | 拒绝写入或发布，保留错误原因 |
| 唯一性 | 确认重复的多余赛事届次记录数 / 实际新增数 | 0%；疑似重复未解决数 0 | 暂缓相关候选，人工/AI辅助比对，不按名称相似直接合并 |
| 及时性 | 发布前关键来源核验距发布 ≤24 小时的记录数 / 发布数 | 100%；报名中记录的关键来源复查间隔目标 ≤24 小时 | 未复查不得新发布；存量标为需复核，避免继续声称已验证 |
| 来源可用性 | 内容可读且与当届赛事相关、最终地址正确的关键链接数 / 受检关键链接数 | 发布验收 100%；不是仅检查 HTTP 200 | 标记来源失效或访问受限，禁用失效证据入口；补源前阻断发布 |
| 可追溯性 | 有批次、来源、证据、核验主体、时间、规则/模型版本、决策原因的新增记录数 / 实际新增数 | 100% | 缺审计记录不得验收；不得补造历史审核时间 |
| 写入安全 | 版本检查及写后读取对账成功批次数 / 写入批次数 | 100%；每批最多 25 场 | 冲突中止、重读并判重，不覆盖他人修改 |

关键字段无原文依据即为未通过，不能把“格式正确”当成“事实正确”。98% 是非关键字段的人工抽查验收目标，不是已测得准确率，更不是允许 2% 的新闻入库。

## 4. 抓取与解析标准

- 抓取前检查 robots 和站点访问限制；每次跳转重新检查目标，记录禁止、访问受限、超时等原因。不得以代理绕过限制。
- 同站请求间隔默认至少 1.5 秒；站方要求更严格时遵从站方；429/503 进入退避，不密集重试。
- URL 仅删除已知跟踪参数；保留语言、地区、分页和业务参数；签名 URL 不随意改写。canonical 是对齐线索，不能不核对就合并不同届次或不同语言内容。
- 默认每文件不超过 8 MiB，响应头及读取过程中均检查；仅处理所需类型，保留 HTML、JSON、PDF、Word 章程的按需支持。超限内容留线索待处理，不记为不存在赛事。
- 增量抓取、缓存策略须遵守响应约束；配置和策略版本写入批次报告。未实现的 ETag 等能力不得宣称已启用。
- HTML 实体、空白、编码和日期格式规范化；日期保留原文与原时区，展示使用北京时间。不得推断缺失报名时间、费用或资格。

## 5. 审计与异常闭环

1. 每批逐条执行硬门槛、确定性校验、去重及写后对账，不能以抽样替代。
2. 发布前由管理员按来源域和专业分层抽查：每批至少抽取 max(5, 向上取整(批次数量×20%)) 条，不足 5 条全查；保留抽样 ID、抽样方法和结果。
3. 新来源、读取受限、近期误收来源、来源跳转异常、疑似重复等高风险条目必须全查，不得只参与随机抽样。
4. 任一非赛事、范围不符、虚构证据或关键事实错误：阻断该批次通过，检查同批及同源记录；修正后重新验收，不能删除错误样本来提高通过率。
5. 疑似严重错误先暂停相关发布并保留恢复信息。永久删除仍由管理员明确确认；回滚仅作用于本批新增 ID，旧记录和后续他人修改不覆盖。
6. 待办必须有负责人和期限。运营目标：发现严重问题后 1 小时内响应、24 小时内完成隔离/补源/退回决定；普通问题 3 个工作日内处理或记录外部阻碍及下一次检查日期。当前无排班与告警闭环时，该时效记“尚不具备保障能力”。

角色：抓取程序负责请求与日志；Kimi 负责证据辅助判断，不是最终责任人；管理员负责例外、抽查与发布；维护人员负责规则、回归测试和回滚。任务无人认领时必须显示“未分配”，不能显示“人工审核中”。

## 6. 批次交付模板

每次报告至少包含：batch_id、rule_version、开始/完成时间、写前/写后版本、备份位置、原始候选数、URL去重数、抓取成功/受限/失败数、线索保留数及原因、实际新增ID清单、合格草稿数、发布数、官方待公布数、隔离数、确认/疑似重复数、各质量指标分子分母、抽查记录、待办负责人、回滚范围。

每条核验清单包含：赛事ID、标准名称、届次、主办方、地域、参赛对象、专业分类、资格与专业任务摘录、官方来源/报名网址/最终地址、日期原文与解析值、核验时间、核验主体、AI模型及提示词版本（若使用）、结论与原因。

官方待公布数是草稿/发布中的交叉统计，不能与二者相加冒充总数。流程失败时仍须输出失败报告；实际新增以数据库读取结果为准，搜索命中量不是新增量。

## 7. 必须保留的回归样本

- 广西财经学院获某大赛一等奖：获奖新闻，非赛事条目。
- “有哪些学科竞赛可以参加……竞赛清单”：目录文章，只作线索。
- “兰州城市学院创新创业学院”“大赛动态”“国赛公告”：机构/栏目，非赛事。
- 青少年篮球赛、文化艺术季：不属于大学生专业赛事。
- 同一比赛在两个网站的转发：一场赛事、多个证据，不新增两场。
- 正常大学生程序设计/医学/农学/法律/专业设计赛事：材料充分时允许进入合格草稿，不因冷门或无独立域名误拒。
- 无日期资料与官方明确待公布：必须得到不同结果。

## 8. 实施现状（2026-09-22）

已部署：抓取参数规范化、逐跳 robots 检查、请求限速改进、类型与流式大小限制；新增/改名记录的范围及最低资料字段门槛；采集不合格候选写入线索报告；Kimi 提示词先检查页面身份；新转换记录不默认官方待公布。相关 64 项测试通过，但这些测试不代表全库 SLA 达标。

部分实现：证据与审核信息已有字段，尚未按本 SLA 全面结构化；线索目前主要为文件报告，没有完整后台线索处理界面；字段齐全检查不能证明事实真实；旧记录未全部重新核验。

待实现/验收：统一证据级准入和赛事身份去重、误收隔离及恢复流程、Kimi 结论到处置的完整联动、质量看板与分层抽样、告警排班、增量缓存和 canonical 策略、全导入路径一致性验收。未完成前不得对外声称“全面达到 SLA”或“保证不误收”。

变更本文的范围、阈值或例外须升版本并记录原因；不得为凑新增数量临时放宽标准。

### 实施补记：2026-09-22 误收隔离

增加 `quarantined` 可恢复状态，保留来源、原状态、隔离原因、时间及规则版本；普通赛事列表与审核列表不展示隔离记录，可在赛事列表状态筛选中查看并编辑。恢复必须重新通过范围及最低资料门槛，只能恢复为草稿，不能直接发布。定时 Kimi 审核中的高风险 `event_identity` 结论与明确非赛事标题可触发隔离；单纯“证据不足”不会触发。隔离同步移除公开缓存，并退出定期重复审核。

本阶段不代表全部审核入口已经统一，也没有完成全库清洗、身份级证据核验、线索工作台和统计看板。隔离记录仍保留在底层管理数据以便恢复，统计实际比赛数量时必须排除该状态。
