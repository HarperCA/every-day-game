# 抓取结果账口径

后台「任务与反馈 → 抓取结果账」读取管理员接口 `listPipelineRuns`。抓取流程每轮结束时写入 `savePipelineRun`，以运行目录名称为唯一标识，重复写入会更新同一轮，不会重复计数。最近保留 100 轮。

- **搜索结果**：各来源返回的条目总数，同一赛事可能在多个来源出现。
- **去重后线索**：判重为 `new` 的页面数，尚未证明是合格比赛。
- **符合赛事范围**：入库程序通过大学生专业赛事范围检查、进入收录评估的候选数；不是最终合格数。
- **新增入库**：本轮成功写入数据库的新记录数，可能包含待核验草稿。
- **通过收录初审的新增**：新增记录中收录判定为 `admit` 的数量，仍可能等待字段或来源核验。
- **实际发布**：本轮成功写入公开缓存的新增和已有记录数之和，两者另行显示。
- **旧记录补齐**：本轮更新旧记录且至少补上一个原先为空的核心字段，或增加一条新核实的官方来源的数量。
- **费用**：Jev 使用响应中的实际美元费用，包含首轮和通知追溯二次分类。百度、正文抽取与入库审核尚无逐轮可核对的结算数据，显示「未记录」，不并入已知费用。
- **失败原因**：按预筛、抓正文、赛事范围与收录步骤分别统计。历史记录只有原日志保存的部分，缺项显示「未记录」。

每轮本地还留有 `runs/<运行标识>/result-ledger.json` 和原始候选、抽取与筛选报告。读写结果账都要求管理员身份；该功能不调用模型。旧运行可用 `backfill-pipeline-ledger.mjs <runs/目录>`预览，确认后加 `--write`；只有日志明确记载新增及更新均为 0 时才回填零值。
