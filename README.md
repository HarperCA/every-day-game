# 竞赛雷达（后端重构分支）

大学生竞赛推荐微信小程序：学生按专业、级别、报名时间找比赛，看详情、收藏、设报名提醒，问赛事助手；管理员在后台审核、发布。
比赛数据由每晚自动流程从官网、通知里找来，AI 抽取字段，每个字段附原文出处，审核通过才公开。

这个文件夹是**后端重构**的工作目录（分支 `feat/pipeline-skeleton`，从 main 的 `8265574` 拉出）。
重构前的线上版本在 main 上打了标签 `legacy-20261028`。分支和提交的规矩见仓库根目录的 AGENTS.md（这个文件夹里不显示，在桌面 `每日竞赛` 文件夹里）。

## 为什么重构

- 线上后端分在两处：美国服务器（原云函数代码跑在兼容外壳上）、上海云开发（9 个云函数）；
- 自动流程靠多个各自定时的脚本拼起来，前一步没跑完后一步也会开始；
- 全部比赛存在一个大文档里，每改一条整份读写，多个任务同时改容易冲突；同一个比赛每出一届就换一个新编号；
- AI 接口散在各处，Kimi、DeepSeek 等各管各的密钥和用量。

## 重构后的安排

- **服务器**：主库留在美国服务器；上海云开发换成北京服务器（2026-11-07 起正式开发）；去掉兼容外壳（翻译层），后端代码直接运行，不再假装成云函数。
  - 美国：主库（比赛、届次、来源）、每晚流程、后台、Codex（本机调用）。
  - 北京：小程序入口（备案域名 xiaohuiworks.cn）、用户数据（账号、收藏、提醒）和发提醒、首页列表和详情（美国推来的公开比赛副本和海报）、收集报错、替美国代读国内网页。
- **AI**：只保留 DeepSeek 接口，其余由 Codex 替代；全部经 AI 总管统一调用和记账。
- **每晚流程**：只有启动按时间触发，后面按顺序一个模块跑完再跑下一个，模块内部并发；当晚结果先存在当晚的小库里，全部跑完才统一写进主库。
- **数据库**：仍用 SQLite，拆成比赛（一级）和届次（二级）两级，收藏挂比赛、提醒挂届次。比赛库在美国，用户库在北京，互相同步一份只读副本。

在本地写完、测试通过后再部署；部署前先把线上版本下载下来对比、先备份，不整体覆盖服务器。

## 目录

这个文件夹只显示新代码。小程序、后台、旧脚本等旧代码仍在同一个仓库、同一条分支里，只是不放在这个文件夹（用 git 的稀疏检出隐藏）；
要看旧代码，打开桌面上的 `每日竞赛` 文件夹（main）。

```
backend/
  美国/          美国服务器：比赛库（db/）、每晚流程（pipeline/）、AI 总管（ai/）
  北京/          北京服务器：用户库（账号、收藏、提醒、纠错提交、公开副本）、小程序要用的 5 项服务
  沟通/          两台之间的来往：公开比赛同步、用户数据同步、代读网页（两端放在一起）
  共用/          两边都用的：数据库读写方法、基础工具、测试工具
  Environment/   装的第三方库、要设的环境变量、测试配置
README.md
```

每个文件夹里有 README.md，写着作用、状态和还没定的事。
有代码要测的文件夹里有 `test/`，只测这个文件夹的代码：`test/单独/` 是测试，`test/复用/` 是好几个测试共用的工具（假接口、样例数据），放在使用者共同的上一级。

## 装库、跑测试

```powershell
cd backend/Environment
pnpm install --ignore-workspace    # 第一次用时装库
pnpm test                          # 跑 backend/ 下全部测试
```

需要 Node 22 或以上、pnpm 10。测试全部用假接口和内存里的库，不连真实接口、不花钱、不碰线上数据。

## 每晚流程试跑

```powershell
node backend/美国/pipeline/run.mjs --dry-run                   # 试跑：最后不写主库
node backend/美国/pipeline/run.mjs --run 2026-10-29 --from 05  # 接着某一晚，从第 5 个模块重跑
```

运行记录在 `backend/美国/pipeline/日志/<日期>/`（run.db、run.log、report.md），保留 90 天，不进 git。

## 还没定的

- 空壳页用什么重读（Codex 还是无头浏览器）；图片文字识别留不留。
