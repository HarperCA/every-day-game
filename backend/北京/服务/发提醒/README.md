# 发提醒（北京/服务/发提醒）

到时间的提醒发订阅消息；保存提醒时按到期时间排好，不靠每几分钟扫一遍。美国推来的报名时间变了，就调整已设的提醒。

- **接替**：上海云函数 sendReminders
- **读写的数据**：副数据库：reminder
- **现在的状态**：能用，有测试（2026-11-02）。上海时期分两半：上海 sendReminders 管提醒数据（列出、领取、回写），美国 reminder-dispatcher 排计划、到点发微信。北京合在一处：
  - `状态机.mjs`：上海的列出、领取、回写、回收超时，规则原样，存取改成用户库
  - `调度.mjs`：美国的排计划、发送（稳定版凭证）原样，原来经网络调上海，现在直接调本机状态机
  - `reminderDelivery.js`：上海原样（发送内容、重试规则、北京时间格式）
  - 保存提醒后用户数据服务把两小时内到期的交给 `排上`；其余每小时对账一次排进计划
  - `跟上时间.mjs`：美国推来的报名时间变了，调整待发送的提醒（2026-11-02）。规则照旧小程序提醒页的 syncReminderTarget：只动 pending 的；预设提前量的提醒时间跟着挪，自定义的不挪；标 time_updated。旧的要用户打开提醒页才对，北京改成对账前全部对一遍、到点领取前再对这一条
- **不做**：旧的“赛事取消、延期”（schedule.change_status）线上全是 normal，新比赛库没有这个字段。
- **要注意**：截止提前、提醒时间落进两小时内的，要等下一次对账（每小时）才排上，最多晚一小时发；推后的不受影响（领取前会再对）。
- **安全**：`handle` 会交出 openid，只给本机调度用；北京入口不对外开放这个服务，带用户身份调用一律拒绝。
