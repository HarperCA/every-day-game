# 搬旧数据（北京/搬旧数据）

把上海云开发里的旧用户数据搬进北京：账号、收藏、提醒、偏好、纠错、意见反馈进副数据库（用户管理中心），报错日志、加载统计进报错库（2026-11-02）。**只用一次**，正式切换时跑。

```
搬旧数据/
  转换.mjs   纯计算：上海的文档 → 北京的行，每个不搬的记一条原因
  搬.mjs     只往空库里搬，副数据库一个事务写完，写完逐表、逐条核对
  运行.mjs   命令行入口，写报告
  test/
```

## 怎么搬

| 上海 | 北京 |
|---|---|
| user_account | 编号原样保留（令牌、提醒、收藏都按它对上）；没有 openid 的不搬 |
| favorite（挂届次） | 改挂比赛：按美国导出的届次对照找比赛；同一人收藏同一比赛的几届合成一条，留最早的；对不上的不搬 |
| reminder、user_preference | 照旧字段，去掉 `_id`、`data_version`；提醒状态（授权、发送、时间变动）原样保留 |
| feedback、general_feedback | 照旧字段。10-13 演练时上海这两个集合是空的：纠错和意见反馈当时在美国旧服务器上，正式切换时要从美国旧库另外导出成同样格式的 .json 放进同一个文件夹 |
| client_issues、client_stats | 进报错库，报错按时间先后 |

挂在不存在的账号下的、必填缺了的、取值不在名单里的都不搬，报告里按原因列出编号（报告不带 openid 和用户写的内容）。

## 怎么跑

1. 美国导出届次对照（含回收站里的届次）：
   ```bash
   node backend/美国/db/建库/届次对照.mjs --出 <届次对照.json>
   ```
2. 上海只读导出（`scripts/server/export-shanghai-users.py --env <环境> --out <文件夹>`，旧仓库里的工具）。正式切换要在上海停写之后导出最新的。
3. 搬：
   ```bash
   node backend/北京/搬旧数据/运行.mjs --旧数据 <上海导出的文件夹> --届次对照 <届次对照.json>
   ```
   不给 `--目录` 写到 `数据/试搬-<时间>/`（不进 git）；正式切换把 `--目录` 指到北京的 `DB_DIR`，那里必须还没有数据。

导出的文件和搬出来的库都是线上用户数据，不进 git。
