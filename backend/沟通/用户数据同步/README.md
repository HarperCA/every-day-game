# 用户数据同步（沟通/用户数据同步）

**方向**：北京 → 美国

把北京用户库的账号、收藏、提醒、意见反馈、纠错、偏好，和收集报错库的加载统计、报错日志，同步一份到美国的**只读副本**（`美国/db/用户副本`），给美国后台的访问异常、问卷统计、意见反馈、纠错审核看（2026-11-02，用户定用户数据传回美国）。

**不传 openid、appid、unionid**（用户 11-02 同意）：后台审查用不到，发提醒只在北京发，少一份身份信息出境。

## 怎么同步

做法和公开比赛同步一样，方向相反：

- 每 10 分钟一次（北京定时跑 `北京端.mjs`）。只推有变化的：每行整理后内容的哈希和上次比，没有变化一个请求都不发；删掉的（取消收藏、删提醒）也推。
- 每 24 小时整体重推一次，最后一批带“收尾”，美国清掉这一轮没收到的（比如美国从备份恢复后多出来的），两边不会慢慢走样。
- 报错日志只增不改：记住推到第几条，接着往后推；整体重推时从头推。
- 美国确认收下才记进度（状态文件）；中途断了下次重推，重推不会出错（有就覆盖）。
- 签名、5 分钟时效和公开比赛同步共用一套（`../公开比赛同步/格式.mjs`），同步秘钥 `SYNC_SECRET` 两条同步共用一把。

一开始没用“变更记录”（原设想在正本库每次写入自动记一行），改成和公开比赛同步一样按内容哈希比：不用改 `共用/db`，用户库的量（几千行）每 10 分钟全读一遍很快。

| 文件 | 跑在哪 | 做什么 |
|---|---|---|
| 格式.mjs | 两边 | 同步哪些表、账号去掉哪些字段、一批的格式 |
| 北京端.mjs | 北京服务器 | `推送(...)`：读用户库、报错库，比出变化，分批签名发给美国。`node 北京端.mjs [--full] [--dry-run]`，要 `USER_SYNC_ENDPOINT`、`SYNC_SECRET(_FILE)`、`DB_DIR`，状态文件 `USER_SYNC_STATE_FILE` |
| 美国端.mjs | 美国服务器 | `接收(...)`：验签，写进用户副本。单独一个只听本机的小服务（`USER_SYNC_PORT`，默认 4332），nginx 把 `/sync/user` 转进来 |

## 现在的状态

## 规矩

两端放在同一个文件夹里，格式和密钥规则只定一次；只经 `共用/db/index.mjs`、`美国/db/index.mjs`、`北京/主数据库/index.mjs`、`北京/副数据库/index.mjs` 和 `北京/服务/收集报错/报错库.mjs` 读写数据库；只走服务器之间，不经过小程序。
