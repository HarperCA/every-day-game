# 沟通（backend/沟通）

美国和北京两台服务器之间来往的代码都在这里。每条来往一个文件夹，**两端放在一起**：美国那一端、北京那一端在同一个文件夹，格式和密钥规则只定一次，改一边时另一边就在旁边。

| 文件夹 | 方向 | 做什么 |
|---|---|---|
| 公开比赛同步/ | 美国 → 北京 | 已公开的比赛、届次推到北京的公开副本，小程序从北京读 |
| 用户数据同步/ | 北京 → 美国 | 账号、收藏、提醒、意见反馈、纠错、偏好和报错日志同步一份只读副本到美国（不带 openid），给后台审查 |
| 审核结果回传/ | 美国 → 北京 | 后台审核纠错、处理意见反馈的结果写回北京正本，用户在小程序里看得到 |
| 代读网页/ | 美国 → 北京 → 国内网站 | 每晚流程读不到的国内网页由北京代读 |

## 两边的数据谁说了算

| 数据 | 正本（能改） | 副本（只读） |
|---|---|---|
| 比赛、届次（已公开的） | 美国比赛库 | 北京用户库的公开副本 |
| 账号、收藏、提醒、意见反馈、纠错、偏好、报错日志 | 北京用户库、报错库 | 美国用户副本 |

每张表只有一边能改；副本用 `readOnly: true` 打开（`共用/db`），业务代码写不进去，只有同步能写。所以两边不会同时改同一条。

## 同步怎么做（两条同步共用的做法）

- **只传变了的**：按每条内容的哈希和上次推的比，删掉的也推；分批发，对方确认写入后才记进度，中途断了下次重推（有就覆盖，重推不出错）。（原设想用正本库的变更记录，实现时改成按哈希比，不用改 共用/db。）
- **每天整体重推一次**：防止两边慢慢走样。
- **都要带密钥**，只走服务器之间，不经过小程序。

## 规矩

- 每个文件夹里：`美国端.mjs` 跑在美国，`北京端.mjs` 跑在北京，`README.md` 写清楚格式。
- 读写数据库只经 `共用/db/index.mjs`、`美国/db/index.mjs`、`北京/主数据库/index.mjs`、`北京/副数据库/index.mjs`。由 `test/单独/structure.test.mjs` 检查。

## 现在的状态

只读副本的开关能用（`共用/db`）。公开比赛同步、用户数据同步、审核结果回传能用（2026-11-02，两条同步都按内容哈希比变化）；代读网页还是骨架占位。
