# 审核结果回传（沟通/审核结果回传）

**方向**：美国 → 北京

美国后台审核纠错（采纳、驳回）、处理意见反馈（状态、公开回复、内部备注）、审核校赛管理员申请和校赛（2026-11-08）后，把结果写回北京副数据库的正本，用户在小程序“我的纠错”“我的反馈”里看得到（2026-11-02，用户同意这个做法）；校赛只有审核通过（已发布）才在小程序发布。

为什么要单独一条：美国的用户副本是只读的，改了也到不了用户手里；纠错和意见反馈的正本在北京。

- 一次一条：`{ 种类: '纠错' | '意见反馈' | '校赛管理员' | '校赛', 编号, 改动, 读到的更新时间 }`。纠错只能改 `status`；意见反馈能改 `status`、`public_reply`、`internal_note`。
- 校赛两种（2026-11-08）：都只能改 `status`、`review_note`。
  - `校赛管理员`：`status` 只能 `已通过` / `已拒绝`；北京调副数据库的 `校赛.处理管理员申请(db, 编号, { status, review_note }, { 读到的更新时间, now })`，美国写进用户副本的 `school_admin`。
  - `校赛`：`status` 只能 `已发布` / `已拒绝` / `已下架`；北京调 `校赛.处理校赛(...)`（参数同上），美国写进 `school_contest`。
  - 拒绝、下架必须写 `review_note`（`review_note_required`）；状态不对 `invalid_school_status`。这两条北京端先查，不合规的不碰库。
  - 北京副数据库还没有 `校赛.*` 时回 422 `school_review_not_ready`（先部署美国、后部署北京时后台会看到这句）。
  - 错误码按结尾归：`…_not_found` 回 404，`…_conflict` 回 409（校赛操作冲突时和纠错一样报 `feedback_conflict`）。
  - 审核说明写进 `review_note` 传回北京（负责人在小程序里看得到），美国比赛库的后台记录里也留一份。
- 带上后台读到的最后修改时间：北京那边对不上（别的管理员刚改过）就不覆盖，回 409 `feedback_conflict`。规则照旧上海 `adminData/generalFeedback.js`：已解决必须写公开回复。
- 北京交回改好的那一行，美国顺手写进自己的用户副本，不用等下一轮用户数据同步。
- 审核的说明、采纳后把届次转待人工审核，都记在美国比赛库（后台记录），不传北京。
- 签名、5 分钟时效和公开比赛同步共用，同步秘钥 `SYNC_SECRET` 共用一把。

| 文件 | 跑在哪 | 做什么 |
|---|---|---|
| 美国端.mjs | 美国服务器 | `回传(...)`：签名发给北京，成功后写进用户副本。后台服务把它包好放进环境，要 `SYNC_REVIEW_ENDPOINT`、`SYNC_SECRET(_FILE)` |
| 北京端.mjs | 北京服务器 | `接收(...)`：验签，调副数据库的 `纠错.处理`、`意见反馈.处理`。单独一个只听本机的小服务（`BEIJING_REVIEW_PORT`，默认 4333），nginx 把 `/sync/review` 转进来 |
