# 推荐排序（backend/共用/推荐排序）

《第一步：排序规则》的实现，首页列表（北京 用户呈现模块）和赛事助手（美国）共用这一份。只有规则，纯计算、不碰数据库；
各自的“排序工具”从自己那台服务器的库里取条目，交给这里排。外面只经 `index.mjs` 用。

规则从旧代码搬来，逻辑不变（publicData 的 publicQuery.js、listOrder.js、preferenceMatch.js、competitionRanking.js、competitionValue.js、majorKeywords.js）；
测试的期望值是用旧代码在同样输入下算出来的，保证搬过来排序不变。字段用新比赛库的名字。

只有一处按规则改了旧代码：搜索词对得上专业时，旧代码只按专业筛，名称里有这个词、专业不对的会漏掉（搜“设计”漏掉“程序设计天梯赛”）；
规则 ① 写的是“名称命中的在前、只是专业对得上的在后”，所以名称命中的也留着（2026-11-01）。

| 规则 | 文件 | 状态 |
|---|---|---|
| ① 搜索：名称命中在前、只是专业对上的在后；搜索词像专业名的对到十三类 | 列表顺序.mjs、专业关键词.mjs（+ 专业目录-2026.json，教育部本科专业目录） | 能用 |
| ② 专业大类、省份筛（没有搜索词时；偏好还是面板由调用方决定） | 列表顺序.mjs | 能用 |
| ③ 状态分组：报名中 → 时间待公布（含即将报名）→ 比赛中 → 比赛已结束 | 报名状态.mjs | 能用 |
| ④ 组内分档：收藏且提醒 → 只收藏 → 只提醒 → 其他（收藏是比赛编号、提醒是届次编号，调用方传） | 列表顺序.mjs | 能用 |
| ⑤ 截止日：越近越靠前；已过截止的离今天越近越靠前；没有截止日的在后 | 列表顺序.mjs | 能用 |
| ⑥ 综合分：七个维度加权（目标匹配、推荐等级、紧迫度、机会窗口、专业匹配、参与门槛、信息完整），再做多样性重排 | 综合分.mjs、价值分.mjs | 能用 |

入口：`排列表(条目们, 条件, now)` 一次做完 ①–⑥，交回排好的条目（带 列表分组、搜索块）和搜到的专业。
其余筛选（级别、参赛形式、费用、是否停办……）和分页不在这里，由调用方做。日期一律按北京时间。

价值分、报名时间可靠度旧系统发布时算好存着，新比赛库不存，用到时当场算（价值分.mjs）。
