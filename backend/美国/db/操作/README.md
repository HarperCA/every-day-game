# 操作：怎么读写

和 `描述/` 同级，对外提供复用接口；外面经 `db/index.mjs` 用，不直接引用这里的文件。
规则全部从 `描述/` 读：写入前怎么校验、能按哪些字段筛选，这里不再另写一遍。

| 文件 | 内容 |
|---|---|
| index.mjs | 打开库（默认美国比赛库，可传北京的表和结构；readOnly 只读副本）；读（get、list）、筛选（find、count）、写（insert、update、remove、transaction） |
| 校验.mjs | 写入前按 `描述/` 检查：未知字段、必填、类型、长度、可选值 |
| 筛选.mjs | 把筛选条件转成 SQL：等于、在其中、比较、包含文字、列表里有、没填、或者；排序 |
| 编码.mjs | 列表、对象存成 JSON，是否存成 0/1，读出来再转回去 |
| 错误.mjs | 统一报错 DbError，按 kind 区分 |
| 内部.mjs | 只给本文件夹用：取底层连接写连表查询 |
| 比赛.mjs | 按名称或别名找、某个比赛的全部届次、全部连届次（后台列表）；后台写入：新建、编辑、删除（连同届次进回收站）、恢复、彻底删除 |
| 届次.mjs | 届次连比赛一起筛：关键词、级别（届次没填用比赛的）、专业、数据状态、报名还没截止；后台写入：新建、编辑、改状态、删除、恢复、彻底删除 |
| 搜索记忆.mjs | 每个比赛一份 Markdown 的搜索记忆：解析、生成、初始、读、写、改节、补齐（2026-11-07）；11-08 加“维护记录”一节（最近 5 条、最新在前，每条截到 200 字，整份超 8000 字先删最旧的维护记录；旧记忆没有这节当空的，改节时补上） |
| 爬虫脚本.mjs | 每个比赛一份爬虫脚本（打开、等待、点击、取列表的步骤）：校验步骤、读、写、记结果（2026-11-08） |
| 指纹.mjs | 每个比赛一份通知列表指纹：算指纹、比对、读、记、记检查（2026-11-08） |
| 后台写入.mjs | 只给本文件夹用：只放行可改字段、找出真正变了的字段、记 manual_fields、留后台记录、生成编号 |

## 写入的规矩

- 新增：补上 `描述/` 里的默认值、版本号 1、建立时间，校验通过才写。
- 修改：改动合并到原记录；有版本号的表（比赛、届次）必须带上读到的版本号，对不上报“版本冲突”，成功后版本号加一。
- 后台写入（`比赛.*`、`届次.*` 的新建、编辑、改状态、删除、恢复、彻底删除）：只改 `可改字段`（给用户看的那些），人工改过的字段记进 `manual_fields`，每个都在一个事务里并在后台记录（audit_log）留一条。
- 删除：比赛、届次先打删除标记（`deleted_at`），默认读不到；删比赛连同它的届次。后台比赛管理点删除，回收站恢复，每天清理 30 天前的（`后台/每日清理.mjs`）。
- 事务：一组读写放进 `transaction`，任何一步出错整个撤回；指向的记录在事务提交时才检查。
- 时间字段按实际时刻比较和排序，`+08:00` 和 `Z` 两种写法混在一起也不会比错。

只管存取，不做业务判断：发布条件、收录门槛、提醒什么时候发，留在用到的地方。
