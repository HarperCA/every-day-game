# 建库：把旧比赛数据搬进新的比赛库

旧数据只读、不改；新库写到一个新文件，已有的库文件不覆盖。随时可以删掉新库重来。

```
建库/
  旧字段.mjs     旧总表每条记录有哪些字段（2026-10-30 按线上全部 380 条补全），哪些不搬、为什么
  转换.mjs       纯计算：旧记录 → 比赛、届次、来源、处理记录，合并、拆开、规整，每个问题记一条
  搬比赛.mjs     一个事务写进比赛库，任何一条出错整个撤回
  核对.mjs       写完逐条检查旧记录里每个有值的字段在新库里都找得到
  报告.mjs       写给人看的建库报告
  运行.mjs       命令行入口
  届次对照.mjs   每一届属于哪个比赛（含回收站里的），给北京搬旧用户数据时把旧收藏改挂比赛（2026-11-02）
  test/
```

## 怎么跑

1. 从美国服务器只读导出旧总表（`/opt/daily-contest/server/data/app.db` 的 documents 表，`admin_state/competitions` 那一条），放进 `../数据/旧数据/`（不进 git）。
2. 运行：

```bash
node backend/美国/db/建库/运行.mjs --旧数据 backend/美国/db/数据/旧数据/<导出的文件>.json
```

不给 `--库` 时写到 `../数据/建库试跑/比赛库-<导出时间>.db`，旁边是同名的 `-报告.md`。

## 怎么搬

| 旧 | 新 |
|---|---|
| 每条记录 | 一届（`edition`，编号不变），挂在一个比赛（`competition`）下 |
| 同一 eventId、名称规范化后相同的几条 | 同一个比赛的几届，按年份排顺序；比赛级字段取代表那届（已发布 > 已归档 > 草稿，再看最近修改） |
| dataStatus | 新的三种状态：published → 已发布，archived → 已归档，其余（旧数据里只有 draft）→ 待人工审核，理由写“旧系统的草稿，未审核”；状态时间取发布、归档、首次发现的时间 |
| 旧的审核字段（数据状态、系统校验、人工审核、待确认清单、归档时间和原因、下一届估计、替代关系、名录批次……） | 届次的 `legacy`，原样保留（2026-10-31 新结构只留状态、理由、状态时间） |
| 上级比赛就是自己 eventId 的（借用了上级的编号） | 拆成独立比赛：编号把 `edition-` 换成 `event-`，上级指向原编号 |
| schedule、track 的字段 | 届次上单独的字段 |
| sources | 来源表一行一条 |
| aiReview 等 9 种 AI 和核验过程 | 处理记录表 |
| 新结构没有单独字段的（追溯任务状态、分诊、隔离记录等） | 届次的 `legacy`，原样保留 |

规整只做不改意思的：空字符串当没填、文字写的数字转数字、数字写的年份转文字、只写日期的时间原样存。
过不了校验的选填字段：原值移进 `legacy.未通过校验`，字段留空，报告里记一条；必填的过不了，这一届不搬，报告里写明。
