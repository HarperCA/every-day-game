   `日期 成功/失败：摘要（原因）`，原因去掉换行、截到 120 字，没有原因不带括号。如“2026-11-08 成功：没有变化（指纹和上次一样，跳过）”“2026-11-08 成功：改了 2 处”。

7. **兜底**（2026-11-08 审查）：整个维护一个包在 try/catch 里，任何异常都按失败收尾（摘要“出错”，原因写错误），照常写后台记录、维护记录、维护时间。
   **额度类错误**收尾后再往外抛，让 `运行.mjs` 停批：AI 错误种类（`ai/common/errors.mjs`）是 额度用完、密钥错误、搜索超限的；
   以及文字看得出的余额不足（DeepSeek 402 归成“请求有误”）、额度用完（入库工具出错时把错误包成普通错误、丢了种类）。

试跑：照常判断（读全文照读），脚本、指纹、记忆、维护时间、后台记录都不写，入库按试跑（不写主库）。

### 成功/失败和摘要（2026-11-08 用户定）

每次维护交回、并写进后台记录 detail 的 `成功`（布尔，后台按它上色）和 `摘要`（固定文字，后台原样显示）；`结果` 照旧留着（更细，运行入口按它分组），`原因` 写清楚（失败时一定有）。

入库工具交回后：**新建** = 入库类型是新比赛或新一届、并且真的写进主库（入库工具给每个条目的 `写进` 为真，2026-11-08 审查）的条数；**改动** = 各条目 `改动` 的总条数；
**对上已有** = 入库类型是补来源并且 `写进` 为真，或已处理过（本来就在库里）。

| 情况 | 成功 | 摘要 |
|---|---|---|
| 新建 > 0 或改动 > 0 | 是 | 入库 N 条 / 改了 M 处 / 入库 N 条，改了 M 处 |
| 都是 0，但至少一条对上了已有届次（入库类型 补来源并且写进了、已处理过） | 是 | 核对无误 |
| 网站说没更新 / 指纹没变 / 只少了条目 | 是 | 没有变化 |
| 带比赛名的条目全被挑通知排除（获奖公示等；原因写排除了哪些） | 是 | 没有新通知 |
| 没找到官网，但权威名单里有这个比赛 | 是 | 只有权威名单 |
| 读了全文都不是这个比赛的 | 否 | 没发现这个比赛的通知 |
| 交给入库了但一条都没过（06 丢掉、失败等；不审核以后不再有 05 丢掉的；原因写每条的状态和原因） | 否 | 被审核挡掉 |
| 没找到官网（起点候选都不算官网，DeepSeek 没找到或找到的不算官网；转没转待人工审核都算；权威名单里也没有的也算） | 否 | 没找到官网 |
| 找到的官网打不开；起点候选没有是官网的、有打不开的（浏览器也打不开，第三方通知也没入库东西）；旧脚本打不开列表页（连续不到 3 次）；写脚本时起点打不开 | 否 | 官网打不开 |
| 官网打不开或没找到官网，用高校转发通知入库了或改了字段 | 是 | 入库 N 条 / 改了 M 处 |
| 写不出脚本（第一次写、或旧脚本跑不通重写失败，非网络原因）；连续 3 次写不出后 30 天内轮到 | 否 | 写不出爬虫脚本 |
| 入库工具交回 写入.error（写主库出错）；找官网搜索出错（DeepSeek 接口出错、Tavily 也没找到）；维护过程中抛了异常（兜底） | 否 | 出错 |

后台记录 detail：`{ 结果, 成功, 摘要, 原因, 入库: [{ 网址, 状态, 原因, 入库类型, 写进 }], 改动: [{ 届次, 网址, 字段, 改前, 改后 }], 过程 }`，
改动的网址是依据的那条通知；过程里有一条“核对”写改了什么（没改写“没有要改的字段”）。返回值也带 `改动`。

## 爬虫脚本是什么样

一串步骤，程序照着操控网页或无头浏览器取通知列表，不在服务器上运行 AI 写的代码（格式和校验在 `db/操作/爬虫脚本.mjs`）：

| 动作 | 字段 |
|---|---|
| 打开 | 网址 |
| 等待 | 选择器，或毫秒（最多 15000） |
| 点击 | 选择器（要浏览器） |
| 取列表 | 条目（CSS 选择器）；标题、链接、日期（相对条目，不给就用条目里第一个链接） |

最后一步是取列表，最多 20 步。写脚本时程序先把页面压缩成只剩结构的 HTML（`爬虫/压缩.mjs`）；AI 每轮交回“要看”（最多 3 个网址）、“规则”或“做不到”，
程序试跑：取到条目、并且有条目带比赛名或者至少 3 条就算写好，不合格把结果和列表页结构告诉它再改，最多 3 轮。
直接下载只拿到空壳页（看得到的字不到 200）、或者 AI 说做不到时，改用浏览器打开后的页面。
AI 交回的 JSON 解析不出来（ai.chat 抛“格式不对”）算这一轮没按格式回答，告诉下一轮接着写；浏览器起不来当这一页打不开（原因以“浏览器打不开”开头），都不抛出。

照脚本爬（`爬虫/执行.mjs`）失败时交回 `失败类`：`'网络'`（打不开、超时、HTTP 错误、robots 不允许、浏览器打不开或中途关掉、页面跳到不安全的地址，重写也没用）
或 `'取不到'`（取不到条目、选择器出错、点击/等待找不到元素、步骤不对、脚本里的网址不安全、列表页不是网页，要重写）；成功、没更新时为 null。

## 调度（`调度/`）

每个比赛多久查一次，按离预计报名时间还有多久分档（一个月按 30 天算）：

| 情况 | 多久查一次 |
|---|---|
| 还有 4 个月以上（窗口外） | 每 3 个月 |
| 还有 2–4 个月 | 每月 |
| 还有半个月–2 个月 | 每半月 |
| 还有半个月以内 | 每周 |
| 过了预计时间半个月以内，还没发现新一届 | 每周 |
| 过了半个月–3 个月 | 每月 |
| 过了 3 个月以上 | 每 3 个月 |
| 正在报名中 | 每月 |
| 没有预计时间 | 每月 |

- 预计报名时间看最新一届：报名开始还没到就用报名开始；已截止的用每日归档存的下一届预计，没存就用报名开始（没有就比赛开始）往后推 365 天；最新一届一个时间都没有时用上一届推。
- 上次检查用比赛的 `last_maintained_at`，加上间隔就是下次检查；从没查过的马上查。
- 先查谁：间隔短的先，同样间隔的越早该查的越先。

## 后台多选的维护队列（2026-11-12）

用户定：“这套 AI 审查（Codex，手动勾选）把这一套删掉，这一套使用新维护进行替代，然后就是可以选择任意数量的比赛进行手动勾选”。

- 后台比赛列表勾选比赛点“维护选中”（动作 `启动维护`），比赛排进维护队列（`db/操作/维护队列.mjs`，admin_state 的 `ai_maintenance_queue`）。**不设上限**：前端、动作、队列加入都不限数量。
- 定时器 `competition-radar-ai-queue` 每 2 分钟跑 `运行.mjs --队列 --并发 4 --报告 …/队列-日期-时分.json`：
  - 队列空（排队、正在都没有）马上退出，不拿锁、不打印；
  - 每晚流程在跑（`PIPELINE_LOG_DIR/.运行中.lock`）、或维护锁被占（每天 10:00 那次、上一轮队列还在跑；锁是 `共用/工具/运行锁.mjs`，目录 `MAINTAIN_LOG_DIR`）就打印一句跳过，下次再看；
  - 拿到锁：额度暂停还没到点就不跑；先把上次异常退出留下的“正在”收回排队最前；再从队列逐个领（同时 4 个，`--并发` 可改），每个用 `维护一个` 处理（和每日那次一样：找官网、爬通知、核对字段、发现新届直接入库），
    做完在队列里标完成，记进“最近”（成功、摘要、结果、原因、时间；最多 30 个）；维护一个一般的异常记失败“出错”，接着下一个；一直做到队列空（运行中新排进来的也接着做）。
  - AI 额度用完、余额不足、搜索超限、密钥错误（同 跑一批）：这个比赛放回排队最前，不再领新的，在跑的跑完，写 2 小时暂停（admin_state 的 `ai_quota_pause`），剩下的留在队列；暂停期间每轮都跳过，到点接着做；没停批、有做完的就清掉暂停。
  - 每晚流程中途开始了：不再领新的，剩下的留在队列。
  - 报告只在真跑了比赛时写；`--试跑` 只读打开，按队列名单跑一遍，不改队列。
- 后台：比赛行上排着的显示“排队中”、正在做的显示“维护中”（可以同时好几个），做完看维护时间的红绿和详情（和每日那次一样，都是 audit_log 的“新维护”记录）。
  总览顶上的“维护进度”读 `维护队列.读进度`：正在维护哪几个、排队几个、最近完成的成功失败、暂停到。

## 找新一届（`找新一届/`，2026-11-12）

用户定：“先让用户看到现在能报名的比赛”，**发现新一届就入库发布**，追不到官方通知也用高校转发发布，标明来源。
试验（线上 `/opt/competition-radar/experiments/找新一届-20261112/`，20 个已归档比赛发现 6 个新一届）暴露的问题——挑战杯被写成别的比赛、拿错通知
（社团招新、校赛实施方案、承办申报）、学校内容混进去（“我校本科生”、主办方写成某大学、校内截止当报名截止）、学校页被标成官方来源、
选择题 4000 token 被截断漏了蓝桥杯、多届次标题只看第一个届次、30 天窗口太短——都由下面的程序规则把关。

**挑哪些比赛**（`挑比赛.mjs`）：最新一届（ordinal 最大）已归档；预计报名时间（调度的 `检查频率`）已过或 60 天内（推不出预计的也找，排最后）；
7 天内找过的不找（上次找的时间看后台记录 audit_log 里 action“找新一届”最新的一条，不改比赛表、不加字段）；预计时间离今天近的先；`--上限` 默认 30。

**找一个**（`index.mjs` 的 `找新一届`）：

1. 最新一届不是已归档的不找（摘要“不用找”）。库里最新一届的届次、年份：届次从 `edition_ordinal`、没写从届次全称认；年份从 `edition_year`、没写从全称认，
   都没有就取这一届报名、比赛日期里最晚的年份（跨年办的按结束那年算，免得把同一届当新的）。
2. **搜**（用途 `new_edition_search`，DeepSeek 搜索 API）：“比赛名 下一年”“比赛名 下一届”（认不出届次的只搜年份），末尾带 `after:日期`——
   **第一次**从上一届结束（比赛结束 → 报名截止 → 比赛开始 → 报名开始；都没有用最新一届那年 1 月 1 日，再没有就一年前）开始；
   **之后**从上次找的前 3 天开始（收录有延迟）。去掉屏蔽网站和备案、统计类网站，同一网址留一次，最多 20 条。
3. **程序先筛**（`核对.mjs`）：标题是招新、承办申报、校赛/实施方案、获奖公示结果报道类的排除（国家级比赛再加赛区、省赛通知）；
   标题和摘要都没有比赛名（`名称写法` 任一）的排除；标题认得出届次或年份、而且不比库里新的排除（旧届）；
   网址像列表页、栏目页、首页的排除；搜索结果 date 或网址里的日期太旧的排除（2026-11-13，见第 5 步）。
4. **DeepSeek 选择题**（用途 `new_edition_pick`，`选择题.mjs`）：每批最多 10 条、token 上限 16000；没选上的不读；回答格式不对的那批当没选。AI 只帮着筛。
5. **读通知、程序再核对**（选上的按“官方网站上的、标题带年份的、日期新的”在前，最多读 6 条）：打得开；页面标题不是排除那类；
   **标题或正文里有比赛名**（程序对不上就不建，不靠 AI 判断是同一比赛）；届次、年份（搜索标题 → 页面标题 → 正文里紧挨着比赛名的）比库里最新一届新。
   - 届次中文、阿拉伯数字互认；**多届次标题**（“第十六届江苏省…暨第二十届全国…”）认紧挨在比赛名前面的那个；挨着的认不出时，标题里只有一个届次才用它。
   - 新届：两边都有届次比届次（冲突时以届次为准），否则比年份（单个年份要比库里最新一届的结束年份大，区间比开头）；比不了的不建。
   - 过了的按新届分组：届次相同、或一方没届次而年份相同算同一届——**同一新届只交一条、只建一次**。
   - 2026-11-13 用户定（和高校转发补救同一套，`核对.mjs`）：页面要是**通知详情页**（读到的像列表也不用）；**发布日期要够新**
     （搜索 date、网址日期、正文发布时间取最早的，要晚于库里最新一届结束、在最近 12 个月内；认不出日期的照用，因为届次年份已核过比库里新）；
     追官方原文读到的页面也这样核。同一次找到几个新届，**只交最新的一届**（一次最多一届）。
   - 网站种类：官方（比赛 website、搜索记忆里核实过的官方域名、来源表官方有效来源的网站；学校部门网站不算）、高校转发（.edu.cn）、其他。
6. **追官方原文**（不是官方网站上的，每个新届追一次）：页面链接和正文网址里指向官方网站的 → 读、核对同一新届；
   指向外部网站（不是学校、政府、备案统计类，链接文字像通知/大赛/官网）的最多 3 个 → 核对过再用 `判断官网` 判断它的首页，是官网才算；
   都没有就在已知官方域名下站内搜“site:域名 比赛名 届次 after:日期”，标题对得上的读最多 2 条核对。
   **追到了用官方通知**；追不到的，高校转发（.edu.cn）用转发发布，其他网站的不用。
7. **入库**：`pipeline/总控/入库指定网址.mjs`，每个新届一条，带 `比赛编号`、`新届 { 年份, 届次 }`（程序认的）、`核对说明`，高校转发的带 `来源类型: 'school_repost'`；
   选项 `更新已有: false`（不改已有届次）、`不审核: true`（04 抽取 → 06，不过门槛直接发布；原最新一届本来就已归档）。
   06 对高校转发：来源 `source_type: school_repost`、`is_official: false`；学校名不进主办方、“我校学生”不进参赛对象；只有交学院的截止的，报名时间留空、`pending_announcement` 为真
   （北京按 `info_source` 是高校转发时显示“以官方通知为准”）；名称按比赛名加年份届次拼；对上已有届次的丢弃。见 `pipeline/modules/06-ingest/README.md`。
8. 写一条后台记录（audit_log，action“找新一届”，detail `{ 结果, 成功, 摘要, 原因, 线索, 入库, 过程 }`）。试跑照常搜、读、交入库（入库按试跑），不写后台记录。
   兜底同维护一个：异常按失败“出错”收尾；额度用完、余额不足、搜索超限、密钥错误收尾后往外抛，运行入口停批。

摘要：入库 N 条 / 拟新增 N 届（试跑）/ 没发现新一届 / 不用找 → 成功；被挡掉（交了入库一条都没建）/ 出错 → 失败。

**以后找到官方通知**：高校转发建的届次没有官方主办方通知，新维护（每日/队列）照常爬官网、挑通知时会对这一届核对：补上官方来源、按维护规则核对字段
（确定事实不同就改、其余只补空，报名时间这时补上）。公开同步的 `info_source` 是从来源推的，补上官方来源后自动变回 `official`。

**运行**：`运行.mjs --找新一届`（`跑找新一届`）：和每日新维护共用维护锁，拿不到就等；每个比赛打印一行，额度类错误停批。
定时器 `competition-radar-new-edition` 每天 14:00（`../../定时/`，还没部署）。

| 挑通知.mjs | 从列表条目里挑交给入库的几条：一届一条主通知（纯函数） |
| 判断官网.mjs | 起点网址是不是官网（程序判断）；从来源表推起点候选；统计每个域名下几个比赛 |
| 调度/ | 多久查一次、挑到期的 |
| 找新一届/index.mjs | 找新一届主流程（搜、筛、选、读、追官方、交入库） |
| 找新一届/核对.mjs | 程序核对：比赛名、本赛届次（多届次标题）、新不新、排除哪类通知（纯函数） |
| 找新一届/选择题.mjs | 给 DeepSeek 的选择题（每批最多 10 条） |
| 找新一届/挑比赛.mjs | 挑这次找哪些比赛；上次找新一届的时间 |
| 找官网/ | 没官网时用 DeepSeek 搜索 API 找（见它的 README） |
| 爬虫/执行.mjs | 照脚本取通知列表（取源码或浏览器） |
| 爬虫/写脚本.mjs | AI 写脚本、程序试跑，最多 3 轮 |
| 爬虫/压缩.mjs | 交给 AI 前压缩页面；判断空壳页 |
