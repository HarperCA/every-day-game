## 流程（`维护一个.mjs`）

1. 读这个比赛的搜索记忆。
2. **官网起点**（2026-11-08 用户定：**先判断是不是官网再维护**）。判断用 `判断官网.mjs`（程序判断，不调 AI；规则见那个文件开头）。

   2. **每个候选都用 `判断官网()` 判断**，第一个“是”的当起点；不是的写进过程，如“官网字段 https://www.bift.edu.cn/：学校主站，不算官网，跳过”。
      同一网址只判断一次；判断抛错算“不是”（原因“判断出错（…）”）。起点用**原网址**，判断时打开后跳到别的网址的在过程里写“（打开后跳到 ××）”。
      来源候选跳过的来源也写进过程（“来源表：××：学校主站”）。
   - 都不是、但有候选**打不开**（判断官网的原因以“打不开”开头：超时、5xx 等，可能只是临时的；2026-11-08 审查）：失败“官网打不开”，
     原因写哪个打不开（“起点候选打不开：官网字段 ×× 打不开（超时）”），**不调找官网、不转待人工审核**、不记教训，下次再试。
   3. 都不是（也没有打不开的）才**找官网**（`找官网/`：DeepSeek 搜索 API 只搜一次比赛名，去掉屏蔽网站留前 10 条，DeepSeek 选一条，程序打开核实）。
      **找到的也要过判断**：先判断官网首页（和来源候选一样，独立官网从首页开始写脚本），不是再判断 DeepSeek 选的网址（平台上的比赛专页、学校网站里的比赛子站）；
      过了才往下走（写脚本/照脚本爬、比指纹、挑通知、入库审核），找官网交回的记忆改动（记官方域名）也只在过了时写；不算官网时改记一条教训。
   - 找官网结果是网络问题（选的官网打不开）：跳过，下次再试，不转，摘要“官网打不开”。
   - **DeepSeek 也没找到、或找到的不算官网：停下**，不写脚本、不读通知、不入库审核，失败“没找到官网”。
     原因写清楚 DeepSeek 为什么没找到（或找到的首页、网址各为什么不算）和每个起点候选为什么不算，如
     “DeepSeek 认为前 10 条里没有官网；起点候选都不算官网：官网字段 https://www.bift.edu.cn/ 学校主站；来源表里的官方来源 https://x.cn/ 页面上没有比赛名（标题：…）”。
     - **来源里有权威名单**（`authority_notice`，如省教育厅公布当年竞赛名单的 PDF；同样要官方、有效）：用读网页打开名单——
       名单里有比赛名 → **成功“只有权威名单”**，原因如“没找到官网（……）；用权威名单核对：名单里有这个比赛（名单网址）”；
       名单打不开或里面没有比赛名 → 失败“没找到官网”。两种都不入库、不转待人工审核，照常写维护时间、后台记录、维护记录。
     - 来源表里有别的官方有效来源（不管推没推出候选、判断成什么）：不转待人工审核。
     - **这个比赛一点官方来源都没有**（website、记忆域名不算来源）：**最新一届转待人工审核**，状态理由写清楚哪天、搜了什么、为什么没找到（如“新维护 2026-11-08：找不到官网（DeepSeek 搜索「××」，DeepSeek 认为前 10 条里没有官网：……），原来是已发布，转待人工审核”），后台留一条“新维护转待人工审核”；人工定过状态的届次不动。
   - 域名比赛数（来源候选认平台用，`算域名比赛数(db)` 全表统计）：一次运行共用，`运行.mjs` 跑一批时算一次从选项传给每个比赛；单独调 `维护一个` 没传就按比赛库算一次、按库缓存。只在用到来源候选时才算。

## 爬虫脚本是什么样

一串步骤，程序照着操控网页或无头浏览器取通知列表，不在服务器上运行 AI 写的代码（格式和校验在 `db/操作/爬虫脚本.mjs`）：

| 动作 | 字段 |
|---|---|
| 打开 | 网址 |
| 等待 | 选择器，或毫秒（最多 15000） |
| 点击 | 选择器（要浏览器） |
| 取列表 | 条目（CSS 选择器）；标题、链接、日期（相对条目，不给就用条目里第一个链接） |

最后一步是取列表，最多 20 步。写脚本时程序先把页面压缩成只剩结构的 HTML（`爬虫/压缩.mjs`）；AI 每轮交回“要看”（最多 3 个网址）、“规则”或“做不到”，
程序试跑：取到条目、并且有条目带比赛名或者至少 3 条就算写好，不合格把结果和列表页结构告诉它再改，最多 3 轮。
直接下载只拿到空壳页（看得到的字不到 200）、或者 AI 说做不到时，改用浏览器打开后的页面。
AI 交回的 JSON 解析不出来（ai.chat 抛“格式不对”）算这一轮没按格式回答，告诉下一轮接着写；浏览器起不来当这一页打不开（原因以“浏览器打不开”开头），都不抛出。

照脚本爬（`爬虫/执行.mjs`）失败时交回 `失败类`：`'网络'`（打不开、超时、HTTP 错误、robots 不允许、浏览器打不开或中途关掉、页面跳到不安全的地址，重写也没用）
或 `'取不到'`（取不到条目、选择器出错、点击/等待找不到元素、步骤不对、脚本里的网址不安全、列表页不是网页，要重写）；成功、没更新时为 null。

## 调度（`调度/`）

每个比赛多久查一次，按离预计报名时间还有多久分档（一个月按 30 天算）：

| 情况 | 多久查一次 |
|---|---|
| 还有 4 个月以上（窗口外） | 每 3 个月 |
| 还有 2–4 个月 | 每月 |
| 还有半个月–2 个月 | 每半月 |
| 还有半个月以内 | 每周 |
| 过了预计时间半个月以内，还没发现新一届 | 每周 |
| 过了半个月–3 个月 | 每月 |
| 过了 3 个月以上 | 每 3 个月 |
| 正在报名中 | 每月 |
| 没有预计时间 | 每月 |

- 预计报名时间看最新一届：报名开始还没到就用报名开始；已截止的用每日归档存的下一届预计，没存就用报名开始（没有就比赛开始）往后推 365 天；最新一届一个时间都没有时用上一届推。
- 上次检查用比赛的 `last_maintained_at`，加上间隔就是下次检查；从没查过的马上查。
- 先查谁：间隔短的先，同样间隔的越早该查的越先。

## 运行

```bash
node backend/美国/db/新维护/运行.mjs [--比赛 编号,编号] [--上限 20] [--试跑] [--写脚本用kimi] [--报告 文件]
```

没指定比赛就按调度挑到期的，逐个维护；每个比赛打印一行“编号：成功/失败，摘要（原因）”；一个出错记下原因接着下一个，AI 额度用完、余额不足、搜索超限、密钥错误就停（维护一个收尾后只往外抛这几类）。跑完打印成功、失败、出错各几个和按摘要分组的个数（`汇总` 也交回按结果分组的）。判断官网要的域名比赛数一批只算一次。浏览器程序要先装（见 `../../web/浏览器/README.md`）。
