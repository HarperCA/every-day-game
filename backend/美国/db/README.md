# 比赛库（backend/美国/db）

美国服务器上的**比赛库**：比赛、届次、来源、处理记录、后台记录、不收录名单、拒过的网址、搜索记忆、爬虫脚本、指纹记录。读写方法在 `backend/共用/db/`（和北京共用），这里只放美国自己的表、建表语句和常用查询。
存什么、什么时候改由用到它的地方决定：每晚流程（最后一步统一提交）、后台。北京的库在 `backend/北京/主数据库/`（公开副本）和 `backend/北京/副数据库/`（用户管理中心）。

```
美国/db/
  index.mjs        唯一入口：openDb() 打开比赛库（默认 DB_DIR/比赛库.db），比赛.*、届次.* 常用查询
  描述/            每张表的字段：必填还是选填、类型、长度上限、可选值（字段类型在 共用/db/字段类型.mjs）
  操作/            比赛、届次的常用查询（按名称或别名找、某比赛的届次、届次连比赛筛选）和后台写入（新建、编辑、改状态、删除、恢复）
  图片总库/        海报和候选图的文件（默认 DB_DIR/海报/，文件名是内容哈希）；届次的 poster、poster_candidates 只记文件名
  结构/            美国比赛库的建表语句（node backend/美国/db/结构/生成.mjs 生成）
  导出/            把比赛库导出成 比赛/000001/比赛.json、01-2025届.json …，只用来看和备份
  建库/            把旧数据搬进新表，只用一次
  test/            测入口和引用规矩；test/复用/ 是比赛库的样例数据
  数据/            本地的库文件（不进 git）；服务器上用环境变量 DB_DIR 指定
```

## 爬虫脚本、指纹记录（2026-11-08）

新维护用，每个比赛各一行，编号就是比赛编号；单独两张表，改它们不动比赛的版本号，只在美国。比赛彻底删除时连带删。

- `crawl_script`（`操作/爬虫脚本.mjs`，接口 `爬虫脚本.*`）：Codex 按官网写的一串步骤，程序照着操控网页或无头浏览器取通知列表，不运行 AI 写的代码。动作只有 打开、等待、点击、取列表，最后一步是取列表，最多 20 步；还记要不要浏览器、谁写的、上次跑通时间、连续失败次数和原因。`写` 第一次不带版本号、之后带读到的版本号，重写后失败数清零；`记结果` 记跑通或跑不通。
- `page_fingerprint`（`操作/指纹.mjs`，接口 `指纹.*`）：通知列表页上次的样子——网站给的 ETag、最后修改时间，通知列表指纹（链接加标题去空白排序后算 sha1，和顺序、日期无关），上次看到的条目（最多 100 条），检查时间、变化时间。`比对` 交回变没变和新增的条目；`记` 指纹变了才改变化时间；`记检查` 网站说没更新时只改检查时间。

## 拒过的网址

`rejected_url`：每晚寻找流程里 03 筛选、05 审核拒掉的候选记在这里（由模块在改动里提、总控统一提交），30 天内 02 对比去重经统一的查询读到就扔。常用操作在 `操作/拒过的网址.mjs`：`近期`（30 天内的）、`清理过期`（每日清理调用，删掉超过 30 天的）。

## 两级结构

- 一级 `competition`（比赛）：编号沿用旧的 eventId，永不改。
- 删除先打标记（`deleted_at`），别处默认读不到，30 天内可恢复。删除用 `共用/db` 的通用接口（标记删除、取消删除、彻底删除），回收站的业务规则在后台 `后台/功能/回收站/`。
- 二级 `edition`（届次）：挂在比赛下，按届次顺序编号；级别、主办方不填就用一级的。
- 收藏挂比赛，提醒挂届次（这两张表在北京用户库）；省赛和国赛是两个比赛，用“上级比赛”关联。

## 规矩

- 外面只能经 `美国/db/index.mjs` 用比赛库；这里只引用自己的文件、`共用/db/index.mjs`、`共用/db/字段类型.mjs`、`共用/工具/`。
- `描述/` 只有数据，不引用任何东西；校验、建表语句、字段说明都从它读，规则只写一遍。
- 每条记录带版本号，修改时版本对不上就报冲突；一次改多条在一个事务里，要么全改要么全不改。
- 导出的文件夹只能看，改数据一律经 `操作/` 的接口。

## 对外接口

和流程现在用的 `美国/pipeline/总控/零件/maindb.mjs`（内存版）一致，换过来时流程代码不用改：

```js
const db = openDb();                        // 打开美国比赛库（DB_DIR/比赛库.db），补执行没执行过的结构文件
// 北京：openMainDb()（backend/北京/主数据库）、openUserDb()（backend/北京/副数据库）；只读副本：openDb({ readOnly: true })
db.get('edition', id)                       // → { version, data } 或 null
db.list('competition')
db.find('edition', { registration_end: { gte: '2026-10-29T00:00:00+08:00' } }, { orderBy: 'registration_end' })
db.transaction(tx => {
  tx.insert('edition', id, data);           // 版本号从 1 开始
  tx.update('edition', id, data, version);  // 版本对不上就抛错，整个事务撤回
});
```

按表的常用查询（例如“报名还没截止的届次”；“某人的收藏”在北京 `北京/副数据库/操作/`）放在 `操作/` 对应的文件里。
