# 每日归档（美国/db/维护/归档）

每天把**报名已截止、还挂着已发布**的届次全部改成**已归档**，并算出**下一届大概什么时候报名**（2026-11-03 用户定）。
放在维护文件夹里，但不走维护“每次一个比赛”的轮流：自己有定时器，每天 2:00（北京时间）跑一次，时间和旧系统 `daily-contest-archive.timer` 一样。

## 规则（照旧系统线上代码，逻辑不变）

- 什么算报名已截止（旧 `publicCache.js` 的 `registrationStatus`）：截止时间已过；没有截止日但比赛已结束；人工指定的报名状态是“已截止”。
  只写日期的截止按北京时间当天 23:59:59 算，所以**截止当天不归，第二天才归**。
- 时间安排有问题的**不归**，等人改（旧 `registrationSchedule.js`）：日期写坏了、开始晚于截止、报名起止都没有又没说明“待公布”。
- 下一届预计（旧 `archiveSchedule.js`）：这一届报名开始时间（没有就用比赛开始时间）往后推 365 天；两个都没有就算不出、存空。**只是参考，不是官方信息**，小程序上要这么写。
- 归档后：状态时间记归档时间，理由写“报名已截止，每日归档自动归档”，存下一届预计（届次的 `next_edition_estimate`，结构/002），后台记录留一条“自动归档”。
- 一届出错（比如刚被人改过，版本号对不上）不挡别的，记失败，第二天再归。

金值：`test/复用/旧代码金值.json` 是旧代码在 17 个边界情况上跑出来的（11-03 从美国服务器拷下的线上代码），新代码逐个对得上。

## 运行

```bash
node backend/美国/db/维护/归档/run.mjs --dry-run   # 只列出会归哪些
node backend/美国/db/维护/归档/run.mjs             # 归档
```
