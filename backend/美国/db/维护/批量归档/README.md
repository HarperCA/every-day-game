# 批量归档（美国/db/维护/批量归档）

把**每个比赛最新一届、还是待人工审核、报名已截止**的届次一次改成**已归档**（2026-11-12 用户定）。手动跑，不挂定时器。
起因：名录导入的届次里有一批“发布前还缺：该届已结束”的，报名早就截止了，一直挂在待人工审核。

## 规则

- 只看没删的比赛的最新一届（顺序最大、没删的那届），状态是待人工审核；给了 `--理由前缀` 的只看最后一条理由以它开头的。
- 报名截止已过才归，按北京时间：只写日期的截止算当天 23:59:59，所以截止当天不归（和每日归档 `../归档/` 一样）。
  没写报名截止的看比赛结束；两个都没有的**不动**；日期写坏了的不动。
- 人工定过状态的（`manual_fields` 含 `status`）不动。
- 归档要过发布门槛的归档那几项（`程序审核` 的 `查发布(记录, { 归档: true })`：标题、范围、名称），过不了的不动，记下原因。
- 归档时：状态时间记这次的时间，理由**接在原来的后面**加一条“<北京日期> 批量归档：报名已截止”（按比赛结束算的另注明），`updated_by` 写“批量归档”，
  后台记录留一条 action “批量归档”。经 `db/index.mjs` 的 `届次.待审归档` 写，每一届一个事务、带版本号；一届出错不挡别的。
- 不算下一届预计（这批多是早年的届次，往后推一年也早过去了）。

## 运行

```bash
node backend/美国/db/维护/批量归档/run.mjs --理由前缀 发布前还缺：该届已结束 --试跑   # 只列出会归哪些
node backend/美国/db/维护/批量归档/run.mjs --理由前缀 发布前还缺：该届已结束          # 归档
```

`--全部待审` 不按理由挑（和 `--理由前缀` 二选一，必须给一个）；`--json` 最后多打一行完整结果。比赛库位置同 `db/index.mjs`（环境变量 `DB_DIR`），在副本上试先把 `DB_DIR` 指到副本所在目录。
