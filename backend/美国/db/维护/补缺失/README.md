# 每日补缺失（美国/db/维护/补缺失）

库里已有的空字段交给 **Codex 补字段**（`美国/补字段/`）去官方网页上找，找得到原文出处的才补（2026-11-03 用户定）。

Codex 补字段很费额度：11-03 线上试跑，每查一条约 8 次 Codex、3 次百度，约 2.5 分钟。所以不走维护每 5 分钟一个比赛的轮流，而是：

- **每天 10:00 跑一次**（北京时间，夜里的流程已经跑完），**最多补 20 条**（`--上限` 可改；跑一周看用量再调）。
- **挑最有用的先补**：已发布、报名还没截止的（没写截止的也算）→ 其他已发布的 → 已归档的；同一档里缺报名时间的排前面。比赛级的问题（主办方、专业分类）按这个比赛有没有这样的届次排。
- **7 天内查过的跳过**，免得每天反复查同一批查不到的（状态文件 `MAINTAIN_LOG_DIR/补缺失状态.json`）。
- 挑出来的交给维护的主流程（审计 → 分流 → 查找 → 组装 → 提交），后台记录和轮流维护一样（检查项“缺失字段”）：
  - 补到的直接改，“维护改正”记录带原文出处；官方写“待公布”的时间标待公布；没补到的留着
  - **已发布、报名还没截止、却补不到报名时间的转人工审核**；补到了别的、报名时间还是没有的，补到的照写，同时转人工
- 和轮流维护共用一把锁；每晚流程还在跑就跳过。

```bash
node backend/美国/db/维护/补缺失/run.mjs --dry-run --上限 2   # 试跑（会问 Codex、花额度，不写库）
node backend/美国/db/维护/补缺失/run.mjs                    # 补
```
