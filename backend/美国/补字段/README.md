# 补字段（美国/补字段）

缺的字段交给 **Codex 代理**到官方网页上找，程序逐个核对，找得到原文出处的才填（2026-11-03 用户定）。
每晚流程的审核（新候选入库前）和维护的“缺失字段”（库里已有的）共用这一个；两边按规矩互不引用，所以单独放在这里（和 `程序审核/` 一样）。

## 怎么找

照 `pipeline/modules/03-filter/Codex代理追踪/` 的做法：Codex 每一轮只做决定（经 AI 总管，用途 `fill`，模型同 `trace`），回一个动作——搜索、读网页或给结论；程序替它执行，把结果交回下一轮，最多 8 轮。

- 搜索：AI 总管的 `search`（百度 → Kimi → DeepSeek 补位；百度占每天的额度）
- 读网页：`美国/web` 自己的程序读，正文截到 6000 字、列出页面里的链接

## 程序怎么核对（不信 Codex 的结论）

每个值都要：网页是这一轮读过、读到正文的；“原文”在网页里（去掉空白和标点比）；而且——

| 字段类型 | 还要 |
|---|---|
| 文字（名称、主办方、参赛对象、资格依据、赛制、报名方式、费用、奖励） | 值在原文里 |
| 日期（报名开始、截止，比赛开始、结束） | 原文写着同一天（2026年9月1日、2026-09-01 都认；只写月日的，网页里要出现过那一年）；带钟点的原文要写着这个钟点 |
| 专业分类 | 十三类之一，有原文依据 |
| 报名入口 | 网址在读过的网页里出现过 |
| 待公布（只限时间） | 原文写着“待定”“另行通知”“以…通知为准”之类 |

核对不过的不填，原因写进结果。

## 字段（`字段.mjs`）

- **必须**：比赛名称、报名开始、报名截止、比赛开始、比赛结束、主办方、参赛对象、大学生参赛资格依据、赛制与规则、专业分类。时间写“待公布”算补齐。
- **能补就补**：报名入口、报名方式、费用、奖励。
- 来源网址不单独补：结果里的 `来源们` 就是核对过的官方网页，调用方拿去当来源。

## 用法

```js
import { 补字段 } from '../补字段/index.mjs';
const r = await 补字段(记录, ['organizer', 'registration_end'], ctx);
// r = { 补到: { 字段: 值 }, 出处: { 字段: { 网址, 原文 } }, 待公布: [字段], 没补到: [字段], 来源们: [{ 网址, 原文 }], 原因 }
```

`ctx` 要有 `ai`（chat、search、报告问题）、`web`（读网页）、`now`，可选 `signal`、`屏蔽网站`。
Codex 交回的格式不对、8 轮都没结论：报告给 AI 总管并抛错；额度用完（`error.kind === '额度用完'`）原样抛出，调用的地方决定顺延。
