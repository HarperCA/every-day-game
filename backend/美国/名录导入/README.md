# 名录导入

把全国比赛名录整理出的比赛写进比赛库，只用这一次（2026-11-04 用户定）。全部是**待人工审核**，学生看不到；公开比赛同步和赛事助手只读已发布、已归档。

## 补充导入（2026-11-06）

用户要把 GitHub `student-competition-review-20261026` 分支 `data/学生比赛名录/2026-11-04补查/` 里剩下的比赛也写进库，批次 `名录导入-20261106`，全部待人工审核，不公开。和第一批的区别：来源核查没做过、没过的也写，理由写清楚，由 AI 审查和人工把关；库里有比赛但没有这一年的挂到已有比赛下（新的排最后，旧的排最前，已有届次不重排）。库里已有这一年、关联库内、回收站、不再收录、未完成、不能入库的不写。撤回：`node 运行.mjs --撤回 是 --批次 名录导入-20261106`，只删还在待审核的。

## 数据

- `全量比赛资料表.csv`：GitHub `HarperCA/college-competition-database` 的 `student-competition-review-20261026` 分支 `data/学生比赛名录/2026-10-26复判/`。
- `可以入库-全量核查结果.csv`：2026-10-27 打开来源网页的核查结果。

## 入哪些

可以入库，且来源核查是“核实”或“大部分核实”。下面这些不入，都写进报告的跳过明细：

- 名称或别名规范化后和库里比赛一样、或已关联库内赛事的（要逐条判断补届次还是跳过）；
- 第 74、1319 行（单独处理）；
- 一条可用来源网址都没有的；
- 同名同年的只留来源最多的一条（和 06 入库判断同一届的规则一致）。

## 怎么写

- 比赛编号 `event-registry-<最小源行号>`，届次 `edition-registry-<源行号>`，来源 `source-registry-<源行号>-<序号>`。同名不同年合成一个比赛的多届。
- 不在可选值里的不写，原文留在届次 `legacy.名录导入.未写入`；研究结论、证据、缺项也都在 `legacy.名录导入`。
- 不带时区的时间只留日期，原文写进时间说明，不替它补时区。
- 来源的核验结果不在可选值里的写 `unchecked`，10-27 打不开的写 `content_unavailable`。

## 和每晚流程的关系

- 02 对比去重不把“全部届次都待人工审核”的比赛算作库里已有，新通知还能往下走。
- 06 入库时新一届只归档已发布的旧届次，待人工审核的不跟着归档，否则会绕过审核公开。

## 怎么跑

默认只试跑，不写库。写之前先备份。

```bash
node 运行.mjs --全量 <全量比赛资料表.csv> --核查 <可以入库-全量核查结果.csv> --报告 <报告.json>
node 运行.mjs --全量 <全量比赛资料表.csv> --核查 <可以入库-全量核查结果.csv> --报告 <报告.json> --写入 是
node 运行.mjs --撤回 是
```

撤回只删这一批还在待人工审核的，已被人发布、归档的留下并报告。

## 转归档（2026-11-04 用户定）

比赛结束日已过的历史届转成已归档，转了会公开到北京。没有结束日期、人工改过、当届、报名没截止的都不转。

```bash

node 运行.mjs --转归档 是 --报告 <报告.json> --写入 是
```
