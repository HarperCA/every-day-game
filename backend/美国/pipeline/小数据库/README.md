# 小数据库（pipeline/小数据库）

每晚寻找流程的当晚小数据库 run.db，单独成组件，对外只给处理接口，谁都不直接碰表。2026-10-31 从总控的零件里拿出来：搜索等模块的“最终结果”接口要自己创建和写入，只调这里的接口。

```
小数据库/
  index.mjs       唯一入口
  库.mjs          openRunDb：打开或创建当晚的库，交回处理接口
  交接检查.mjs    结果的格式检查和统计
  test/单独/
```

## 处理接口

| 接口 | 做什么 |
|---|---|
| `写入结果(模块, { items, changes, problems })` | 先过格式检查，合格才用一个事务写入：条目、每条的经过（记下改之前的样子）、待写进比赛库的改动、模块状态；交回统计。格式不对抛错，一条都不写 |
| `已写入(模块)` | 这个模块写过结果没有 |
| `查找({ kind, status })` | 找当晚的条目，默认找进行中的 |
| `标记线索(模块, [{ key, 原因 }])` | 把条目标成“线索”并写明原因：不往下走，只留作线索（2026-11-01 用户定）。规矩和删除一样 |
| `删除(模块, [{ key, 原因 }])` | 把条目标成“已丢弃”并写明原因，条目和经过都留着（2026-10-31 用户定，不真删）。一批一个事务，有一条找不到、不是进行中或没写原因就一条都不删。模块出错时总控按经过撤回它删的 |
| `创建当晚(信息)` | 记下当晚的运行信息（例如搜索计划、数量），可以重复调用 |
| `activeItems()`、`item(key)`、`trailOf(key)` | 读条目和经过 |
| `changes()`、`pendingChangesFor()`、`markChange()` | 待提交的改动（总控提交时用） |
| `clearModules(模块们)` | 从中间某个模块重跑时，撤销它和之后模块写过的东西 |
| `putBlob()`、`getBlob()` | 网页正文等大块内容 |
| `moduleState()`、`markModule()`、`recordCall()` | 模块状态、调用记账（总控用） |

## 谁能用

- 总控直接引用 `index.mjs`。
- 模块只能经 `ctx.小数据库`（`写入结果`、`创建当晚`、`查找`、`删除`、`标记线索`；模块名由总控填），不 import 这里。
- 这里只用自己的文件和 `backend/共用/工具/`。

以上由 `../test/单独/imports.test.mjs` 检查。
