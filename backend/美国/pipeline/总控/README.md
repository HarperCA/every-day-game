# 总控（pipeline/总控）

每晚流程的“调度员”：按顺序叫 6 个模块干活，限时，关键模块失败就停，最后调 06 入库提供的 写入主库 写进主库、写报告。模块的结果写进小数据库（`../小数据库/`，自带格式检查）：模块自己经 `ctx.小数据库` 写，或者交回给总控代写，走的是同一个接口。
它自己不抓网页、不调 AI、不判断比赛，这些都在 `../modules/` 的各个模块里。

**不能直接运行**：入口是上一级的 `run.mjs`（`node backend/美国/pipeline/run.mjs`），定时器每晚只调用它，它再调用这里的 `runPipeline`。

```
总控/
  orchestrator.mjs    总控本身：一晚从头到尾的顺序都写在这里
  零件/               总控用到的零件，只给总控用，别的地方不能引用
    modules.mjs       模块清单：6 个模块的顺序、名字、是不是关键模块、时间上限；按名字加载模块
    context.mjs       给每个模块准备 ctx：日志、停止信号、额度、是否试跑、读主库、存大块内容、小数据库的接口、调 AI 和读网页
    maindb.mjs        内存里的假主库，只给测试用（正式运行用 backend/美国/db 的比赛库，接口一样）
    report.mjs        当晚总报告 report.md
  test/单独/          测总控：正常流程、失败处理、交接检查、提交、提交后才跑的模块、从中间重跑
```

## 一晚的顺序（orchestrator.mjs）

| 步骤 | 做什么 | 用到的零件 |
|---|---|---|
| 1 加锁 | 同一时间只能跑一次；超过 12 小时没解锁的视为上次异常退出留下的 | — |
| 2 建运行文件夹 | `日志/<北京日期>/`，同一天再跑加 `-02`；删掉超过 90 天的 | — |
| 3 打开当晚小库 | run.db；从中间重跑时先恢复到那个模块之前的样子 | rundb |
| 4 依次运行模块 | 按清单顺序；每个模块开一个 AI 总管会话（来源“每晚自动化”、这一晚、模块名）当 ctx.ai，读网页当 ctx.web；每个模块拿到还在“进行中”的条目和准备好的 ctx，在时间上限内运行 | modules、context |
| 5 交接检查 | 模块交回的结果格式合格才写进 run.db；关键模块失败整晚停下，非关键模块失败记为“跳过”；失败的模块中途经 ctx.小数据库 删过的条目按经过撤回 | handoff、rundb |
| 6 写入主库 | 调 06 入库提供的 写入主库：待写入的用主库的事务写进去，一条候选一组，字段不合格的整组不写；版本号对不上（流程开始后有人改过）的跳过不覆盖；试跑不写。写进去就是发布，没有验收（2026-11-01） | modules/06-ingest |
| 6½ AI 用量汇总 | 不管跑没跑完，都让 AI 总管把这一晚的用量汇总存一份（usage.closeRun） | ai |
| 7 写报告 | 每个模块的结果、条目去向、提交结果、没写进主库的改动和原因 | report |

## 规矩

- 总控只做调度，不放业务规则；判断比赛的规则放在各模块自己的文件夹里。
- 零件只给总控用：总控以外的文件（模块、shared、common）不能引用零件；零件也不直接引用某个模块，模块由模块清单按名字加载。
- 除了 `run.mjs` 和测试，没有文件引用总控。

以上由 `../test/单独/imports.test.mjs` 检查。
