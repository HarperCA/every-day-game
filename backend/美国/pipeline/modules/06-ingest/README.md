## 流程里这一步（入库总管）

逐条做（同一晚两条指向同一个比赛时，第二条能看到第一条已经决定新建）：

1. **对照主库**：名称或别名规范化后一样就是已有比赛。
   - 没有：新比赛；同一晚前面一条已经决定新建的，算它的新一届。
   - 有，但没有这一届（年份或第几届不同）：新一届，顺序接着排；比它早、还没归档的届次一起归档。
   - 有这一届：有新来源就只补来源；来源都有了就是“已处理过”，标已丢弃。
2. **整理字段**（按 `backend/美国/db/描述/`）：
   - 名称里的年份、第几届拆到届次的年份、届次两栏，原文留在届次名称。
   - 编号沿用现有格式：比赛 `event-` 加规范名称算出的 8 位短码（同名同号），届次 `edition-比赛码-年份`（没有年份用 `n顺序`），来源 `source-届次码-序号`。
   - 级别先填“其他/未明确”（抽取里没有，不靠主办方名字猜）；专业分类用三项核验判出来的；空的填 null；参赛形式、费用分档这些没填的由比赛库补默认值。
   - 来源是 05 核验过的官方来源。
3. **发布门槛**（`美国/程序审核`）：没过的不入库，标已丢弃，原因写“06 入库·发布门槛：……”。
4. 报名已截止的为**已归档**，其余为**已发布**；放进小数据库的待写入。

## 写入主库（给总控调）

`写入主库({ 小数据库, 主库, log, 试跑 })`：

- 只写所属条目还在“进行中”的改动；03、05 记的“拒过的网址”不看条目状态。
- 一条候选的改动一组写：主库按字段规则校验，有一项不合格，这条候选的改动全都不写，候选标已丢弃，原因写“06 入库·写入主库：字段不合格：……”。
- 流程开始后有人改过的行（版本号对不上）跳过，不覆盖。
- 出了预料之外的错整个撤回，主库保持原样。
- 每条结果写回小数据库，当晚报告从这里出。试跑不写，只交回能写多少条。
