## 程序去重

按顺序看，碰上一条就扔：

1. 30 天内拒过的网址（03 筛选、05 审核拒的，记在比赛库的 `rejected_url`）。
2. 网址和库里一样：比赛官网、届次报名入口和线索通知、来源网址（含跳转后的）。比的是网址键：不分 http/https，去掉 www、结尾斜杠、锚点、跟踪参数。
3. 在不收录名单里：网址一样，或标题规范化后和名称一样、标题里写着这个名称。
4. 标题规范化后（去掉年份、第几届、引号括号空白、结尾的竞赛/大赛/比赛/挑战赛）和库里某个比赛的名称或别名一样。

认出是库里已有的比赛就扔，不管是哪一届：已有比赛的新一届由 `美国/db/维护/` 的“新一届”检查去找，寻找流程只找库里没有的新比赛。

全部届次都在待人工审核的比赛不算“库里已有”，名称和网址都不参与对比（2026-11-04 用户定）：学生还看不到它们，新通知要能往下走，06 入库时再按名称挂到这个比赛下。

## AI 去重

- 每 20 条一批，连同库里全部比赛（短号、名称、别名、级别、地区）交给 DeepSeek，经 AI 总管 `ctx.ai.chat({ purpose: 'arbitrate', json: true })`。
- 比赛用短号（库1、库2……），AI 回短号，程序换回真正的编号（2026-11-04：线上试跑时 AI 把长编号 event-agent-followup-xxx 抄成 event-xxx，判断是对的，整晚却停了）。
- 每条给出结论：库里已有（附比赛编号）/ 新的 / 拿不准，以及“重复于”（同批前面哪一条说的是同一个比赛）和把握。
- 扔掉：库里已有且把握 ≥ 0.6；和同批前面一条是同一个比赛且把握 ≥ 0.6。拿不准、新的、把握不够的留下，06 入库时还会再对照。
- 出错就截断（2026-10-31 用户定）：
  - 额度不够这一晚要的批数（`ctx.ai.budgetLeft()`）：一次都不调，直接抛错；
  - 接口调用出错：AI 总管已经自己记下，直接抛错；
  - 返回的内容用不了（漏条目、结论不对、比赛编号不在库里……）：先 `ctx.ai.报告问题` 报告给 AI 总管，再抛错。
- 提示词改编自旧的 `adminData/dedupeArbitrationAi.js`：旧的一次问一对，这里一次问一批、对照库里全部比赛。
