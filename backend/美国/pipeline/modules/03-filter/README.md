# 03-filter 筛选

02 对比去重留下的候选在这里分去向：没用的扔掉，只能当线索的标线索，要读的交给 04 读详情和抽取；学校转发、校内选拔、赛事报道这类交给 Codex 追到比赛自己的官方来源，追到的官方来源作为新候选往下走。原来的 04 通知追溯 2026-11-01 并进来。

```
03-filter/
  index.mjs        模块入口，主流程在 筛选总管/
  筛选总管/        主流程：调下面三个，照去向经 ctx.小数据库 查找、删除、标记线索；读不了的网站.mjs
  标题筛选/        程序化筛选，只看标题，给总管提供筛选函数
  Jev筛选/         经 AI 总管 decide（用途 classify）问 Jev 是哪类页面，给总管提供函数；题目.mjs
  Codex代理追踪/   经 AI 总管让 Codex 追到官方来源；prompt.md（提示词）、schema.mjs（每轮的格式和检查）
  test/单独/
```

- **关键模块**：是（11-01 起）。Jev、Codex 出错要截断整晚，和 02 一样；跳过它会把没筛过的候选全送去读详情。
- **现在的状态**：能用，有测试；AI 总管 11-01 起已由 run.mjs 接进流程。

## 流程

1. 平台登记的比赛条目（01 平台脚本来的）不用筛，直接读详情。
2. 标题筛选：标题为空的扔；只有日期地名、校内选拔、赛事报道的去追溯；目录清单、栏目页、只是机构名的标线索；看不出来的交给 Jev。规则搬自 `crawler/lib/jevCandidateFilter.mjs`。
3. Jev 筛选：每条问一次 7 个类别的概率。无关 > 50% 扔，20%～50% 线索；目录清单概率最高的线索；官网、报名入口、主办方通知合计 ≥ 转载、新闻合计的读详情，否则追溯。
4. 判成读详情或线索、但网站读不了（微信公众号、百度百科）或标题是通知的，改去追溯（搬自旧 `run-crawl-pipeline.mjs`）。
5. Codex 代理追踪：Codex 每轮回一个动作（搜索、读网页、给结论），程序替它执行，最多 6 轮，同时追 2 条。搜索经 `ctx.ai.search`，读网页经 `ctx.web.读网页`（美国/web，自己的程序读，不交给 Kimi），交给 Codex 前截到 6000 字并列出页面里的链接。结论里的官方来源由程序核对：必须读过、读到正文、摘录在原文里，一个不剩就改成找不到。

## 去向怎么落

| 去向 | 怎么处理 |
|---|---|
| 扔 | `ctx.小数据库.删除`（标已丢弃并写原因），改动里顺带记“拒过的网址”，30 天内 02 遇到就扔 |
| 线索 | `ctx.小数据库.标记线索` |
| 读详情 | 仍是进行中，`data.筛选` 写明去向和原因 |
| 追溯：找到官方来源 | 官方来源作为新候选（`data.追溯自` 记着是哪条通知追来的），通知标已丢弃；官方来源今晚已经是候选的不重复加 |
| 追溯：不是比赛 | 同“扔” |
| 追溯：只是赛区、找不到、读不出 | 标线索 |
| 追溯：额度用完 | 这条和还没轮上的标顺延 |

## 出错

- 额度不够 Jev 问完这一晚的候选：一次都不调，直接抛错。
- Jev、Codex、搜索调用出错：直接抛错（AI 总管已经自己记下）。
- 返回的内容用不了（Jev 没给概率、Codex 动作不对、6 轮都不给结论）：先 `ctx.ai.报告问题`，再抛错。
- 网页读不到不算出错：告诉 Codex 读不到，让它换办法。
- Codex 额度用完不截断：标顺延。

## 规矩

- 对外只有 `index.mjs` 的 `run(input, ctx)`；`createRun(parts)` 只给测试换假接口用。
- 不 import 别的模块；拒过的网址、读提示词从 `../../common/` 拿；不直接碰 run.db 和比赛库。
