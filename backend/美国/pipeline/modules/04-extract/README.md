# 04-extract 读详情和抽取（字段填写）

读每个候选的详情页，把报名时间、参赛对象、主办方等字段填好，每个字段附原文依据，依据核对不上的删掉。
**先用程序按固定写法填，必要的四项填不齐才交 DeepSeek**（2026-11-01 用户定）。
这个模块不改总库，结果放进条目的 `data.extraction`，交给 05 审核；审核过了，06 入库才写进比赛库。

- **关键模块**：否，失败时记下原因、跳过，继续跑后面的模块
- **现在的状态**：能用，有测试。还没用真实网页和真实 DeepSeek 跑过；程序能填上多少要在服务器上跑过才知道。

## 目录

```
04-extract/
  index.mjs              编排：每条候选依次走下面几步，候选之间并发（同时 4 条）；每晚最多重读 20 条、补读 20 条
  rules.mjs              抽空了没有、关键信息缺哪几项、关键字段数
  schema.mjs             字段名、可选值（报名组织方式、非现金回报和比赛库届次表一致，有测试核对）
  prompt.md              DeepSeek 抽取提示词（extract-v5）
  steps/
    read-source.mjs      1 读正文：读网页读详情页，再读最多 3 个报名入口、通知、附件链接（读网页分好类的），拼成一份正文
    程序填.mjs           2a 程序填：“主办单位：××”“报名截止时间：2026年10月15日”这类写法按固定字段名填，依据就是那一行
    extract.mjs          2 抽取：程序填齐了必要的四项就不调 DeepSeek；没填齐交 DeepSeek，回来的逐字核对，程序填的优先
    原文核对.mjs         逐字核对：AI 给的原文片段回正文找到并扩成整句，找不到的整项删掉（旧代码原样搬来）
    reread.mjs           3 空壳页重读：正文只有导航骨架时，经 AI 总管让 Kimi 执行页面脚本后再读
    supplement.mjs       5 补读：参赛对象或报名时间还缺时，读页面里还没读过的通知链接，最多 2 个
```

第 4 步“抽空了重试一次”在 `index.mjs` 里：主办方、权威信号、回报一项都没抽到时再抽一次，实测同样的输入有时抽空、再跑就正常。

## 必要的四项

主办方、参赛对象（或参赛资格）、赛制、报名截止。程序把这四项都填上了就不调 DeepSeek；
这时权威信号、非现金回报这两个列表是空的，05 的收录门槛仍能从主办方原文判断权威性。

## 程序填的规则

- 只认行首的字段名（可以带“一、”“（一）”“1.”这类序号），后面跟冒号；或者字段名单独一行、内容在下一行。句子中间提到的不算。
- 同一字段取第一次出现的（详情页在前、链接页在后）。冒号后不到 2 个字的不填，长的截到 200 字。
- 报名日期只认写全了年份的；“2026年9月1日至10月15日”这种后一个没写年份的，只填开始，截止留给 DeepSeek。
  只有一个日期时，写了“前、截止、止”的算截止，写了“起、开始”的算开始，都没写的不填。

## 输出

| 情况 | 状态 | 原因 |
|---|---|---|
| 抽取成功 | 进行中 | 抽取完成（仍缺的关键信息写在后面） |
| 读不到，能重试（网络、超时、对方 5xx） | 顺延 | 读不到正文：… |
| 读不到，不能重试；空壳页重读不了或已到上限；DeepSeek 出错 | 失败 | 写明哪一步、什么原因 |
| 停止信号时还没处理到 | 顺延 | 停止信号：下一晚接着做 |

`data.extraction`：`fields`（每项 `{ value, quote }`，列表项各带 quote）、`dropped`（核对不上被删的）、`missing`、`promptVersion`（程序填齐时是 null）、
`程序填了`、`AI填了`、`sourceHash`（正文存在 blobs 里）、`url`、`读过`（读过的网址）、`retried`、`reread`、`supplement`（补读前后缺什么、用没用通知）。

## 调用的外部接口

读网页经 `ctx.web.读网页`（同一网站间隔 1.5 秒）；DeepSeek 经 `ctx.ai.chat({ purpose: 'extract', json: true, promptVersion })`；空壳页重读经 `ctx.ai.fetchPage({ purpose: 'reread' })`（Kimi）。

## 规矩

- 对外只有 `index.mjs` 里的 `run(input, ctx)` 一个入口；`createRun(steps)` 只给测试换假步骤用。

- 交回的每一条都要写明状态和原因，不悄悄丢掉。
