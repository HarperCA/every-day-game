# 搜索词

搜索前的预处理：交回当晚的搜索词给搜索接口用，每个附上理由；搜完把每个词搜到几条记进自己的记录表，第二晚挑词时读。

```
搜索词/
  index.mjs       接口：生成搜索词、记录搜索词
  专业轮换.mjs    挑词规则（从旧的 scripts/server/search-plan.mjs 搬来，规则不变）
  专业目录.json   教育部 2026 年本科专业目录，883 种专业（和旧的 majors-2026.json 相同）
  记录表.mjs      记录表：建表、读历史、写一晚的结果、冷却规则；只给 index.mjs 用
  数据/           记录表的库文件 搜索词记录.db（运行数据，不进 git；第一次记录时自动建）
```

## 接口

- `生成搜索词(ctx, { 额度 = 30 }) → { 搜索词们: [{ 路线, 词, 理由, 专业, 专业代码, 专业类, 门类 }], 平台们: [], 问题们: [] }`
- `记录搜索词(每个词: [{ 词, 路线, 候选数 }], ctx) → { 记录: n }`：主运行文件在结果写进小数据库之后调用，只传搜成功的词。试跑（`ctx.dryRun`）不写；没有要记的词不打开记录表。写不进去只记警告，不让模块失败。

## 挑词规则

- 每晚 30 个（百度每天给自动任务 30 次），全部给细分专业，每个专业搜一次。
- 搜索词是 `专业名 大学生 竞赛 年份 报名`，年份按北京时间，最长 72 字节（汉字算 2），超长时截短专业名。
- 顺序：门类在校生少的先；同一门类先今年新增、再特设（代码带 T）、最后基本专业；再按代码。
- 搜过的 30 天内不再搜；连续两次零候选暂停 2、4、8……天，最长 32 天，到期恢复。

## 记录表

表 `search_term`，每个搜索词一行：

| 字段 | 意思 |
|---|---|
| term | 搜索词 |
| route | 路线（现在都是“细分专业”） |
| last_searched_at | 上次搜索时间 |
| last_candidates | 上次搜到几条 |
| zero_streak | 连续几次零候选 |
| paused_until | 暂停到什么时候，没暂停是空 |
| times_searched | 一共搜过几次 |

搜失败的词不记，第二晚照常排上。

## 没有搬的

旧代码里的“追溯”和“新词试探”两条路线（份额本来就是 0；追溯改由 Kimi 做，用的旧记录字段新库里也没有了），旧的大类词挑法（10-11 起就不用了），以及读后台接口、读写计划文件的部分。平台脚本还是占位，先不列平台。
