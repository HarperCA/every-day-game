# 01-search 搜索

找新比赛的候选网页。原来的“搜索计划”和“发现候选”两个模块合成这一个（2026-10-31 用户定）。
主运行文件 `index.mjs` 只负责按顺序调用下面几个接口，每个接口一个文件夹：

```
01-search/
  index.mjs     主运行文件：搜索词 → 搜索接口 和 平台（同时跑）→ 结果处理 → 最终结果 → 记录搜索词
  搜索词/       返回当晚 30 个搜索词（细分专业轮换，从旧 search-plan.mjs 搬来），自带记录表   能用
  搜索接口/     每个搜索词经 AI 总管搜一次（百度 → Kimi → DeepSeek）                能用
  平台/         针对性平台脚本的集成接口；天池、辽宁各一个文件夹                     集成能用，两个平台占位
  结果处理/     同一网址合成一条候选，记下渠道、搜索词、路线                         能用
  最终结果/     只调小数据库的接口：创建当晚、写入候选                               能用
  test/单独/
```

- **关键模块**：是，模块本身出错时整晚停下、不提交。单个搜索词、单个平台失败只记问题。
- **现在的状态**：主运行文件和五个接口都能用、有测试（两个平台脚本是占位）；AI 总管 11-01 起已由 run.mjs 接进流程（2026-11-04 改正这句旧说明）。
- 和库里对比去重在下一个模块 `02-dedup`。

## 规矩

- 对外只有 `index.mjs` 里的 `run(input, ctx)` 一个入口；`createRun(parts)` 只给测试换假接口用。
- 不 import 别的模块；读网页经 `美国/web/index.mjs`（或 `ctx.web`），AI 经 `ctx.ai`，小数据库经 `ctx.小数据库`。
- 搜索词的记录表是这个模块自己的运行数据（`搜索词/数据/`，不进 git），试跑不写。
- 不直接碰 run.db：最终结果调 `ctx.小数据库` 的接口写入，格式检查在小数据库里。
